# 22.17 - DynamoDB TTL

## Key Concepts

### 1. What is TTL?

**Time To Live** — automatically deletes items after a specified expiration timestamp.

- You define a **TTL attribute** on your table (any name, e.g. `expire_on`)
- The value must be a **Unix Epoch timestamp** (number type)
- When current time > TTL attribute value → item is marked for deletion
- **Does NOT consume WCU** — no extra cost for deletions
- Items are deleted within **48 hours** of expiration (up to 48h delay — exam says "a few days")

---

### 2. How it Works

```
Table: SessionData
┌──────────┬────────────┬─────────────┐
│ user_id  │ session_id │  expire_on  │
├──────────┼────────────┼─────────────┤
│ john_123 │ abc        │ 1700000100  │ ← epoch timestamp
│ alice_456│ xyz        │ 1700003600  │
└──────────┴────────────┴─────────────┘

DynamoDB expiration process:
  1. Scans table, compares expire_on vs current time
  2. Marks expired items
  3. Second process deletes them (within 48h of expiry)
```

TTL is enabled per table via: **Additional Settings → Time To Live → Enable → specify attribute name**

---

### 3. Important Behaviors ⚠️

- **Expired but not yet deleted items** still appear in reads, queries, and scans
  → Must do **client-side filtering** if you don't want stale expired items in results
- When TTL deletes an item → a **delete record appears in DynamoDB Streams**
  → You can recover the item from the stream if needed
- Deleted items are also **removed from LSIs and GSIs** automatically

---

### 4. Use Cases
- Session data expiration (e.g. web session tokens)
- Regulatory compliance (only keep data for N days)
- Reduce stored data / costs by purging old records automatically

---

## Exam Tips
- TTL attribute must be a **Number** type (Unix Epoch timestamp)
- Deletion is **free** — no WCU consumed
- Expired items may still be visible → **filter client-side** if needed
- Deletion delay: up to **48 hours** after expiration
- TTL deletes appear in **DynamoDB Streams** → recoverable
- Items deleted from **indexes (LSI + GSI)** automatically
