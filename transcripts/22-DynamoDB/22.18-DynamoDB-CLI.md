# 22.18 - DynamoDB CLI

> projection-expression and filter-expression already covered in 22.6.

## New Info — CLI Pagination Options

### page-size
- Controls the **size of each individual API call** made under the hood
- You still get the **full dataset** back — just split across many smaller calls
- Purpose: **avoid timeouts** on large tables
- Example: 10,000 items with page-size 100 → 100 API calls of 100 items each → all 10,000 returned

```bash
aws dynamodb scan --table-name UserPosts --page-size 100
# Still returns all items, but uses smaller internal calls
```

### max-items
- Limits **how many items are returned** to you from the CLI call
- Remaining items are NOT fetched — you get a **NextToken** to continue
- Think of it as true pagination from the user's perspective

```bash
aws dynamodb scan --table-name UserPosts --max-items 1
# Returns 1 item + NextToken (if more exist)
```

### starting-token (NextToken)
- Used with `max-items` to fetch the **next page** of results
- Pass the `NextToken` from the previous call as `--starting-token`
- When no `NextToken` is returned → you've reached the end of the results

```bash
aws dynamodb scan --table-name UserPosts --max-items 1 \
  --starting-token <NextToken from previous call>
```

---

### page-size vs max-items

| | page-size | max-items |
|---|---|---|
| Returns | Full dataset | Only N items |
| API calls | Many small ones | Stops when limit reached |
| NextToken | No | Yes (if more items exist) |
| Purpose | Avoid timeouts | True pagination |

---

## Exam Tips
- `page-size` = avoid timeouts, still retrieves everything
- `max-items` = true pagination, returns NextToken
- `starting-token` = continue from a NextToken
- `filter-expression` in CLI = client-side filtering (same RCU cost)
- `projection-expression` = retrieve only specific attributes
