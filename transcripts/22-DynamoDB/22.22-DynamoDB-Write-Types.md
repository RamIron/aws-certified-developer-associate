# 22.22 - DynamoDB Conditional Writes, Concurrent Writes & Atomic Writes

## Write Types Comparison

### 1. Concurrent Writes ❌ (problematic)
Two clients update the same item simultaneously — both succeed, but one overwrites the other.
```
Client 1: SET value = 1  → ✅ success
Client 2: SET value = 2  → ✅ success (overwrites Client 1)
Final value: 2  ← Client 1's write is lost silently
```
**Problem:** both get success but only one actually took effect.

---

### 2. Conditional Writes ✅ (solves concurrency)
Each client adds a condition — only one can win.
```
Client 1: SET value = 1  IF value = 0  → ✅ success (value was 0)
Client 2: SET value = 2  IF value = 0  → ❌ fails (value is now 1)
Final value: 1  ← clean, no silent overwrite
```
This is **Optimistic Locking** (covered in 22.12). One client wins, the other gets a `ConditionalCheckFailedException` and must retry.

---

### 3. Atomic Writes ✅ (NEW — both succeed, values add up)
Both clients increment the value — **both writes succeed** and the result is the sum.
```
Client 1: INCREMENT value BY 1  → ✅ success
Client 2: INCREMENT value BY 2  → ✅ success
Final value: 3  (0 + 1 + 2)  ← both applied correctly
```
DynamoDB applies each increment atomically — no race condition. Used with **Atomic Counters**.

---

### 4. Batch Writes (recap)
One client writes/updates many items at once. Covered in 22.6 (BatchWriteItem).

---

## Summary Table

| Type | Both succeed? | Final value | Use case |
|---|---|---|---|
| Concurrent | ✅ both | Only last write survives | Bug — avoid this |
| Conditional | ❌ one fails | Clean, one winner | Optimistic locking |
| Atomic | ✅ both | Sum of all increments | Counters, stats |
| Batch | ✅ (if no error) | All applied | Efficiency |

---

## Exam Tips
- Concurrent writes = silent overwrite problem → solve with Conditional Writes
- Atomic writes = both succeed, values accumulate → good for counters
- Conditional writes = optimistic locking pattern
- Atomic counters: not idempotent — retrying will increment again
