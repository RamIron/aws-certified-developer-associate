# 22.19 - DynamoDB Transactions

## Key Concepts

### 1. What are Transactions?

**All-or-nothing operations** across one or more items and one or more tables.
Either ALL operations succeed, or NONE of them are applied.

Gives DynamoDB **ACID** properties:
- **A**tomicity — all or nothing
- **C**onsistency — data is always in a valid state
- **I**solation — transactions don't interfere with each other
- **D**urability — committed data is persisted

---

### 2. Read & Write Modes

**Read modes** (3 total):
| Mode | Description |
|---|---|
| Eventually Consistent | Default — may return stale data |
| Strongly Consistent | Always returns latest data (2× RCU) |
| **Transactional** | Consistent view across multiple tables simultaneously |

**Write modes** (2 total):
| Mode | Description |
|---|---|
| Standard | Writes may partially fail across tables |
| **Transactional** | All writes succeed or all fail (2× WCU) |

---

### 3. Transaction APIs

| API | Operations |
|---|---|
| **TransactGetItems** | One or more GetItem operations as part of one transaction |
| **TransactWriteItems** | One or more PutItem, UpdateItem, DeleteItem as part of one transaction |

---

### 4. Capacity Cost — 2× Rule ⚠️

Transactions cost **twice** the normal RCU/WCU because DynamoDB performs two phases:
1. **Prepare** — validates and reserves the operation
2. **Commit** — applies the operation

```
Transactional WCU formula:
  WCU = (writes/sec) × ceil(item_size_KB / 1) × 2

Transactional RCU formula:
  RCU = (reads/sec) × ceil(item_size_KB / 4) × 2
```

**Exam examples:**

| Scenario | Calculation | Result |
|---|---|---|
| 3 transactional writes/sec, 5 KB items | 3 × (5/1) × 2 | 30 WCU |
| 5 transactional reads/sec, 5 KB items | 5 × (8/4) × 2 ← round 5→8 | 20 RCU |

---

### 5. Use Cases
- Financial transactions (debit one account, credit another — atomically)
- Order management (create order + update inventory simultaneously)
- Multiplayer games (update multiple player states at once)
- Any scenario requiring ACID guarantees across multiple items/tables

---

## Exam Tips
- Transactions = **ACID** in DynamoDB
- Always costs **2× WCU and 2× RCU**
- APIs: **TransactGetItems** and **TransactWriteItems**
- Transactional read = consistent view across multiple tables simultaneously
- Standard write = some can fail; Transactional write = all or nothing
- Two internal phases: **prepare** + **commit** (hence the 2× cost)
