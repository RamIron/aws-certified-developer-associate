# 22.8 - DynamoDB Conditional Writes

## Key Concepts

### 1. What are Condition Expressions?

A **ConditionExpression** is an optional parameter you add to write operations.
DynamoDB evaluates the condition first — if it's false, the write is rejected.

Applies to: **PutItem, UpdateItem, DeleteItem, BatchWriteItem**

---

### 2. Available Conditions

| Condition | Description |
|---|---|
| `attribute_exists(attr)` | Succeeds if the attribute exists |
| `attribute_not_exists(attr)` | Succeeds if the attribute does NOT exist |
| `attribute_type(attr, type)` | Checks the data type of an attribute |
| `contains(attr, value)` | String/set contains a value |
| `begins_with(attr, prefix)` | String starts with a prefix |
| `IN` | Attribute value is in a list of values |
| `between :low and :high` | Attribute value is within a range |
| `size(attr)` | Checks the length of a string |
| Comparisons | `=`, `<>`, `<`, `>`, `<=`, `>=` |

---

### 3. FilterExpression vs ConditionExpression

| | FilterExpression | ConditionExpression |
|---|---|---|
| Used for | **Read** operations (Query, Scan) | **Write** operations (Put, Update, Delete) |
| Purpose | Filter results returned to client | Determine if the write should happen |
| Effect on RCU | Does NOT reduce RCU | N/A (write side) |

---

### 4. Key Patterns

#### Never overwrite an existing item (PutItem)
```
ConditionExpression: attribute_not_exists(pk)
→ Only writes if the item doesn't exist yet
→ If item exists → ConditionalCheckFailedException

With PK + SK table:
  attribute_not_exists(pk) AND attribute_not_exists(sk)
```

#### Conditional update (only if price > 500)
```
UpdateItem with:
  UpdateExpression: SET price = price - :discount
  ConditionExpression: price > :limit

→ Price will never drop below the limit
→ If condition fails → write is rejected, no change
```

#### Conditional delete (only if attribute doesn't exist)
```
DeleteItem with:
  ConditionExpression: attribute_not_exists(price)
→ Deletes the item only if it has no price attribute
```

#### Conditional delete (value-based)
```
DeleteItem with:
  ConditionExpression: productCategory IN (:cat1, :cat2)
                       AND price BETWEEN :low AND :high
→ Both conditions must be true for the delete to proceed
```

#### String pattern matching
```
DeleteItem with:
  ConditionExpression: begins_with(imageURL, 'http://')
→ Deletes insecure image URLs only
```

---

## Exam Tips
- ConditionExpression = write-side; FilterExpression = read-side
- `attribute_not_exists(pk)` on PutItem = safe upsert (never overwrites)
- If condition evaluates to false → `ConditionalCheckFailedException`
- Condition Expressions help with **concurrent access** / **optimistic locking**
