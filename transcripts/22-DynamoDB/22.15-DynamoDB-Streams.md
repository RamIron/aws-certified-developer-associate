# 22.15 - DynamoDB Streams

## Key Concepts

### 1. What are DynamoDB Streams?

An **ordered stream** of item-level modifications (create, update, delete) in a DynamoDB table.
Every change to the table appears as a record in the stream, in order.

- Data retention: **24 hours** (must persist elsewhere if you need longer)
- Made of **shards** (like Kinesis Data Streams) — but **auto-provisioned by AWS** (no manual shard management)
- Enabling streams does **NOT retroactively populate** past changes — only new changes appear from the moment you enable it ⚠️

---

### 2. Stream View Types

When enabling a stream, you choose what data appears in each record:

| View Type | What's included |
|---|---|
| `KEYS_ONLY` | Only the key attributes of the modified item |
| `NEW_IMAGE` | The entire item as it looks **after** the modification |
| `OLD_IMAGE` | The entire item as it looked **before** the modification |
| `NEW_AND_OLD_IMAGES` | Both old and new versions — lets you see exactly what changed |

---

### 3. Consumers

Three ways to read from DynamoDB Streams:

| Consumer | Notes |
|---|---|
| **Kinesis Data Streams** | Send stream into KDS → then use Firehose, analytics, etc. |
| **AWS Lambda** | Via Event Source Mapping — invoked synchronously with batches |
| **KCL Application** | Kinesis Client Library app running on EC2 — same API as KDS |

---

### 4. Architecture Patterns

```
DynamoDB Table
    ↓ (changes)
DynamoDB Stream
    ├── Kinesis Data Streams → Firehose → Redshift / S3 / OpenSearch
    ├── Lambda → SNS / filter+transform → DynamoDB / OpenSearch
    └── KCL App (EC2) → custom processing
```

**Use cases:**
- React to changes in real-time (e.g. send welcome email on new user insert)
- Analytics on data changes
- Cross-region replication (Global Tables use Streams under the hood)
- Create derivative/transformed tables in DynamoDB
- Index data in OpenSearch for search capabilities
- Audit/archive all changes to S3

---

### 5. Lambda Integration

- Lambda reads from Streams via **Event Source Mapping** (same pattern as SQS/Kinesis)
- Lambda function needs **IAM permissions** to read from the DynamoDB Stream
- Lambda is invoked **synchronously** with a batch of records
- The Event Source Mapping is an internal process that **polls** the stream and batches records

```
DynamoDB Table → DynamoDB Stream → Event Source Mapping (polls)
                                          ↓ (batch of records)
                                    Lambda function (synchronous)
```

---

## Exam Tips
- Streams retention = **24 hours** — must consume or persist within that window
- Enabling streams does **NOT backfill** past changes
- Shards are **auto-managed** by AWS (unlike Kinesis where you provision shards)
- `NEW_AND_OLD_IMAGES` = see exactly what changed in an item
- Lambda reads via **Event Source Mapping** → invoked **synchronously**
- Global Tables require Streams to be enabled
- KCL works against both DynamoDB Streams AND Kinesis Data Streams
