# 22.23 - DynamoDB Patterns with S3

## Two Patterns

### Pattern 1 — Large Objects

**Problem:** DynamoDB max item size = 400 KB. Can't store images, videos, or large files.

**Solution:** Store large objects in S3, store metadata + S3 URL pointer in DynamoDB.

```
WRITE:
  App → uploads image → S3 bucket
  App → stores metadata + S3 URL → DynamoDB
    { product_id, product_name, image_url: "s3://bucket/img.jpg" }

READ:
  Client → gets metadata from DynamoDB (fast, indexed)
  Client → fetches actual image from S3 using the URL
```

Each service does what it's good at:
- **S3** → stores large objects efficiently
- **DynamoDB** → stores small, indexed, queryable metadata

---

### Pattern 2 — Index S3 Objects Metadata

**Problem:** S3 is not meant for querying. You can't easily ask "find all objects uploaded by user X between date A and B."

**Solution:** Use S3 Event Notifications → Lambda → DynamoDB to maintain a queryable index of S3 objects.

```
App → uploads object → S3
S3 Event Notification → triggers Lambda
Lambda → stores object metadata in DynamoDB:
  { object_key, size, date, owner, content_type, ... }

Now you can query DynamoDB to answer:
  - Find objects by timestamp range
  - Total storage used by a customer
  - All objects uploaded within a date range
  - All objects by a specific user
```

Then use DynamoDB query results to retrieve the actual objects from S3.

---

## Exam Tips
- DynamoDB max item = **400 KB** → use S3 for large objects, store pointer in DynamoDB
- S3 is not queryable → use DynamoDB as a metadata index for S3 objects
- Pattern 2 flow: S3 → Event Notification → Lambda → DynamoDB → queryable metadata
