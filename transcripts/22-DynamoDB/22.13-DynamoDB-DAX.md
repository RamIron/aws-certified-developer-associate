# 22.13 - DynamoDB DAX

## Key Concepts

### 1. What is DAX?

**DynamoDB Accelerator (DAX)** — a fully managed, highly available **in-memory cache** for DynamoDB.

- Microsecond latency for cached reads and queries (vs single-digit ms for DynamoDB)
- **No application code changes needed** — fully compatible with existing DynamoDB APIs
- Solves the **hot key / hot partition** problem (too many reads on the same item → throttling)
- Default TTL: **5 minutes**

```
Without DAX:
  App → DynamoDB table (single-digit ms)

With DAX:
  App → DAX cluster → DynamoDB table (only on cache miss)
              ↑
         microsecond latency on cache hits
```

---

### 2. DAX Cluster

- Made of **cache nodes** — must be provisioned in advance
- Up to **10 nodes** per cluster
- Recommended: **minimum 3 nodes** in production, across **multiple AZs** (Multi-AZ)
- Fully secure: encryption at rest, IAM, VPC, CloudTrail integration

---

### 3. DAX vs ElastiCache

Both are caching solutions, but for different use cases:

| | DAX | ElastiCache |
|---|---|---|
| Best for | Individual item lookups, simple queries, scans | Aggregated/computed results from app logic |
| Integration | Transparent — same DynamoDB API | Manual — app writes/reads from cache explicitly |
| Use case | Hot key relief, read-heavy DynamoDB tables | Store results of expensive computations (sum, filter, aggregation) |

**They can be used together:**
```
App → DynamoDB (raw data) → DAX (cache individual items/queries)
                          → ElastiCache (cache aggregated results)
```

Example: Scan 10,000 items, compute a sum, filter results.
- DAX caches the raw items/scan
- ElastiCache caches the final computed result so you don't re-aggregate every time

---

## Exam Tips
- DAX = in-memory cache for DynamoDB, microsecond latency, no code changes
- Default cache TTL = **5 minutes**
- Solves hot key / throttling problems on reads
- Max **10 nodes** per cluster, minimum **3 recommended** for production (Multi-AZ)
- DAX = simple object/query cache; ElastiCache = computed/aggregated result cache
- They can be used together in the same architecture
