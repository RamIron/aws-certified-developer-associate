# 30.11 — CloudHSM

## What is it?

AWS provisions **dedicated hardware** (Hardware Security Module) for encryption.  
Unlike KMS (where AWS manages keys in software), with CloudHSM **you manage your own keys entirely**.

- **Tamper resistant** — FIPS 140-2 Level 3 compliant
- Supports both symmetric and asymmetric encryption
- No free tier
- Accessed via **CloudHSM client software** (not the standard AWS SDK)
- Good fit for **SSE-C** on S3 (you manage the key, store it in HSM)
- Integration with **Redshift** for database encryption

## CloudHSM vs KMS

| Feature | KMS | CloudHSM |
|---|---|---|
| Tenancy | Multi-tenant | Single-tenant |
| Key management | AWS owned / AWS managed / Customer managed | Customer managed only |
| Key types | Symmetric, Asymmetric, Digital signing | Symmetric, Asymmetric, Digital signing + Hashing |
| Key accessibility | Multi-region (separate keys per region) | VPC-based; shareable via VPC peering |
| Crypto acceleration | None | SSL/TLS offload, Oracle TDE |
| Access control | IAM | CloudHSM own user/permission model |
| High availability | Managed by AWS | Multiple HSM devices across AZs |
| Audit | CloudTrail + CloudWatch | CloudWatch + MFA support |
| Free tier | Yes | No |

## High Availability

CloudHSM clusters span multiple AZs — HSM devices replicate each other.  
Your client connects to any device in the cluster.

## Integration with KMS (Custom Key Store)

You can use CloudHSM as the **custom key store** for KMS:
- Create a KMS custom key store pointing to your CloudHSM cluster
- Services like EBS, S3, RDS use KMS API → KMS routes key operations to CloudHSM
- API calls still logged in CloudTrail

```
Application → KMS API → KMS Custom Key Store → CloudHSM Cluster
```

## Simple Rule

> KMS = AWS manages the keys (simpler, standard)  
> CloudHSM = YOU manage the hardware and keys (stricter compliance, FIPS 140-2 Level 3)
