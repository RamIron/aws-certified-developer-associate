# 30.13 — SSM Parameter Store Hands-On

## Console Walkthrough

**Create a parameter:**
- Name: `/my-app/dev/db-url` (hierarchy with slashes)
- Tier: Standard (free, 4 KB max) or Advanced ($0.05/mo, 8 KB, policies)
- Type: `String` (text/EC2 image ARN), `StringList`, or `SecureString`
- For `SecureString`: choose KMS key (default `alias/aws/ssm` or custom CMK)
- Version history is automatically tracked on every update

**View:**
- SecureString values show as encrypted in the console
- Click "Show decrypted value" → checks your KMS permissions → reveals value

## CLI Demo

```bash
# Get two specific parameters
aws ssm get-parameters \
  --names /my-app/dev/db-url /my-app/dev/db-password \
  --region eu-west-2

# → db-url: plain string value returned
# → db-password: returned as encrypted ciphertext

# Add --with-decryption to decrypt SecureString
aws ssm get-parameters \
  --names /my-app/dev/db-password \
  --with-decryption \
  --region eu-west-2
# → db-password: "devpassword" (plaintext)

# Get all params under /my-app/dev
aws ssm get-parameters-by-path \
  --path /my-app/dev \
  --region eu-west-2

# Recursive: get everything under /my-app (dev + prod)
aws ssm get-parameters-by-path \
  --path /my-app \
  --recursive \
  --with-decryption \
  --region eu-west-2
# → Returns all 4 parameters (dev + prod, decrypted)
```

## Key Takeaway
The hierarchy + `--recursive` flag is powerful for multi-environment apps. A Lambda function can use its environment name to fetch only the relevant path.
