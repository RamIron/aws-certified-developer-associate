# 30.15 — AWS Secrets Manager Hands-On

## Secret Types in the Console

- **Credentials for RDS database** — links to a specific RDS instance; auto-rotation available
- **Credentials for Redshift / DocumentDB / other DB**
- **Other type of secret** — arbitrary key-value pairs (e.g. API keys, tokens)

## Creating a Secret (Other Type)

1. Choose **Other type of secret**
2. Add key-value pairs: `api-key: abc123`, `secret-key: xyz789` (multiple pairs supported)
3. Choose encryption key (default AWS-managed or custom CMK)
4. Give it a name: e.g. `prod/my-secret/api`
5. Add description + tags
6. Configure rotation:
   - Enable → set interval (e.g. every 60 days, max 365 days)
   - Requires a Lambda function — write your own or use AWS-provided for supported DBs
7. Review → Create

## Retrieving the Secret in Code (Python)

```python
import boto3
import json

def get_secret():
    secret_name = "prod/my-secret/api"
    region_name = "eu-west-2"

    client = boto3.client('secretsmanager', region_name=region_name)
    response = client.get_secret_value(SecretId=secret_name)
    secret = json.loads(response['SecretString'])
    return secret['api-key']
```

AWS provides this snippet in the console for Python, Go, JavaScript, Java, etc.

## Rotation with Lambda

When rotation is enabled:
- Secrets Manager invokes the Lambda on the configured schedule
- Lambda updates credentials in the backend (e.g. generates new RDS password, updates the DB, updates the secret)
- For supported services (RDS/Aurora/Redshift), AWS provides ready-made Lambda functions

## Key Difference vs Parameter Store

- Secrets Manager stores key-value pairs (multiple keys per secret)
- Parameter Store stores a single string value per parameter
- Secrets Manager rotation is native; Parameter Store needs EventBridge + custom Lambda

## Cleanup

When deleting a secret, a waiting period is enforced (minimum 7 days) to prevent accidental deletion.
