# 30.8 — Lambda + KMS (Encrypting Environment Variables)

## The Problem

Three levels of "security" for Lambda secrets:

| Approach | Risk |
|---|---|
| Hardcode in code (`password = "supersecret"`) | Anyone with code access sees the secret |
| Plain environment variable (`os.getenv("DB_PASSWORD")`) | Anyone with Lambda config access sees the secret |
| **Encrypted environment variable (KMS)** ✅ | Only users with KMS decrypt permission can read it |

## How to Encrypt Lambda Env Vars

1. Go to Lambda → Configuration → Environment variables
2. Click **Encryption configuration** → Enable helpers
3. Choose a KMS key → click **Encrypt**
4. The value is now stored encrypted at rest

## Code to Decrypt at Runtime

AWS provides a snippet when you encrypt a variable:

```python
import boto3
import os
from base64 import b64decode

ENCRYPTED = os.environ['DB_PASSWORD']

def decrypt():
    return boto3.client('kms').decrypt(
        CiphertextBlob=b64decode(ENCRYPTED),
        EncryptionContext={'LambdaFunctionName': os.environ['AWS_LAMBDA_FUNCTION_NAME']}
    )['Plaintext'].decode('utf-8')
```

## Required IAM Permission

The Lambda execution role must have `kms:Decrypt` on the specific KMS key ARN:

```json
{
  "Effect": "Allow",
  "Action": "kms:Decrypt",
  "Resource": "arn:aws:kms:REGION:ACCOUNT:key/KEY_ID"
}
```

Without this → `AccessDeniedException` at runtime.

## Exam Pattern
> Lambda + encrypted env vars + KMS = attach `kms:Decrypt` to the Lambda execution role
