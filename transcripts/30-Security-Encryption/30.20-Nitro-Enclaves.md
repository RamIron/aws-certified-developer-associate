# 30.20 — Nitro Enclaves

## What is it?

An **isolated, hardened virtual machine** that runs inside a Nitro-based EC2 instance for processing highly sensitive data.

## Why it Exists

Processing sensitive data (PII, healthcare, financial, credit cards) historically required complex VPC isolation. Nitro Enclaves provide a simpler, stronger alternative — an isolated compute environment with extreme constraints.

## What Nitro Enclaves Are NOT
- ❌ Not a container
- ❌ No persistent storage
- ❌ No interactive access (can't SSH in)
- ❌ No external networking

## Key Properties
- Runs on the same host as the EC2 instance (shares CPU/memory/kernel)
- Communicates with the parent EC2 only via a **secure local channel**
- **Cryptographic Attestation** — only authorized (signed) code can run inside
- KMS integration — **only the Enclave** can access sensitive KMS-protected data

## How to Use

```bash
# 1. Launch a Nitro-based EC2 instance with EnclaveOptions = true
# 2. Convert your app to an Enclave Image File (EIF) using Nitro CLI
nitro-cli build-enclave --docker-uri my-app:latest --output-file my-app.eif

# 3. Run the enclave
nitro-cli run-enclave --cpu-count 2 --memory 512 --eif-path my-app.eif
```

## Architecture

```
EC2 Host (Nitro Hypervisor)
├── EC2 Instance (normal)
│   └── communicates via vsock (secure local channel only)
└── Nitro Enclave (isolated)
    ├── No networking
    ├── No SSH
    ├── No persistent storage
    └── Only signed code runs (Cryptographic Attestation)
```

## Use Cases
- Private key processing
- Credit card processing
- Secure multi-party computation
- Any workload requiring highest-level EC2 isolation

## Exam Tip
> "Process sensitive data in an isolated environment on EC2" → **Nitro Enclaves**  
> Key features to remember: no networking, no SSH, cryptographic attestation, KMS integration
