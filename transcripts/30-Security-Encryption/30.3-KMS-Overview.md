# 30.3 — KMS Overview

## What is KMS?

AWS Key Management Service — **AWS manages the encryption keys for us**.

- Fully integrated with **IAM** for authorization
- Every API call to use a key is **audited via CloudTrail** ⭐ exam tip
- Seamlessly integrated with most AWS services (EBS, S3, RDS, SSM, etc.)
- **Never store secrets in plaintext** — use KMS to encrypt them, then store the encrypted value in code or env vars

## KMS Key Types

### By Algorithm
| Type | Keys | Usage |
|---|---|---|
| **Symmetric** | Single key (encrypt + decrypt) | Default for all AWS service integrations. You never see the key — only use via API calls |
| **Asymmetric** | Public key (encrypt) + Private key (decrypt) | For encrypt/decrypt or sign/verify. Public key can be downloaded. Use case: encryption outside AWS by users who can't call KMS API |

### By Ownership
| Type | Cost | Key name format | Notes |
|---|---|---|---|
| AWS Owned Keys | Free | (hidden) | e.g. SSE-S3, SSE-DynamoDB. You don't manage them |
| AWS Managed Keys | Free | `aws/rds`, `aws/ebs`, etc. | Per-service keys, auto-rotated yearly |
| Customer Managed Keys (CMK) | $1/month | Custom name | Full control. Can be imported ($1/month) |

## Key Rotation
| Key type | Rotation |
|---|---|
| AWS Managed | Automatic, every 1 year |
| Customer Managed | Optional automatic (configurable period: 90–2560 days), or on-demand |
| Imported | Manual only (needs alias) |

## KMS Keys are Regional

A KMS key **cannot live in two regions**. To copy an encrypted EBS snapshot across regions:
1. Take snapshot → it's encrypted with KMS Key A (region 1)
2. Copy snapshot to region 2 → AWS re-encrypts with KMS Key B (region 2)
3. Restore snapshot to EBS volume in region 2 using Key B

## KMS Key Policies

Similar to S3 bucket policies — **controls who can access the key**.

> Without a key policy, nobody can access the key.

| Policy | Behavior |
|---|---|
| **Default** | Allows anyone in the account — IAM policies then decide access |
| **Custom** | Explicitly defines which users/roles can use or administer the key |

### Cross-Account Access (custom policy required)
1. Create snapshot encrypted with customer managed CMK
2. Attach custom KMS key policy authorizing the target account
3. Share snapshot with target account
4. Target account creates a copy encrypted with their own CMK
5. Target account creates volume from the copy

## Exam Tips
- KMS = encryption in AWS ✅
- All API calls audited in **CloudTrail** ✅
- KMS keys are **per region** ✅
- Cross-account access requires **custom key policy** ✅
