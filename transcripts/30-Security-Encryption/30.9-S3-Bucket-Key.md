# 30.9 — S3 Bucket Key (SSE-KMS Optimization)

## The Problem

When using SSE-KMS on S3, every object upload/download = one KMS API call.  
At scale, this causes:
- High KMS costs
- Risk of hitting KMS request quota throttling

## The Solution: S3 Bucket Key

A **Bucket Key** is an intermediate encryption key generated by KMS for the S3 bucket.

- KMS generates the bucket key **once in a while** (it rotates periodically)
- The bucket key is stored at the S3 bucket level
- All object encryption/decryption uses the **bucket key**, not KMS directly

### Result
- **99% fewer KMS API calls**
- **99% lower KMS cost** for SSE-KMS workloads
- No security compromise
- **Fewer CloudTrail events** for KMS (since fewer direct KMS calls)

## Diagram

```
Without Bucket Key:
  Each S3 upload → 1 KMS API call (expensive at scale)

With Bucket Key:
  KMS generates Bucket Key → S3 stores it
  All uploads use Bucket Key locally → very few KMS calls
```

## How to Enable

In S3 Console → Create Bucket → Enable encryption → SSE-KMS → **Bucket Key: Enabled** (default now)

Or on existing bucket: Properties → Default encryption → Edit → Enable bucket key

## Exam Tip
> SSE-KMS + high volume of S3 operations → enable S3 Bucket Key to reduce KMS API calls by 99%
> Side effect: fewer CloudTrail events for KMS
