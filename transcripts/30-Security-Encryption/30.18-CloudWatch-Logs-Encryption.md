# 30.18 — CloudWatch Logs Encryption with KMS

## Key Facts

- CloudWatch Logs can be encrypted with KMS keys
- Encryption happens at the **log group level** (not log stream)
- **Cannot** be configured through the AWS Console — must use **CLI or SDK only**
- The KMS key policy must explicitly allow the CloudWatch Logs service principal

## CLI Commands

```bash
# Associate KMS key with an existing log group
aws logs associate-kms-key \
  --log-group-name /aws/lambda/hello-world \
  --kms-key-id arn:aws:kms:eu-west-2:ACCOUNT:key/KEY_ID \
  --region eu-west-2

# Create a NEW log group already associated with a KMS key
aws logs create-log-group \
  --log-group-name /example/encrypted \
  --kms-key-id arn:aws:kms:eu-west-2:ACCOUNT:key/KEY_ID \
  --region eu-west-2
```

## Required KMS Key Policy Addition

The CloudWatch Logs service must be allowed in the key policy. Without this, the `associate-kms-key` call returns `AccessDeniedException`:

```json
{
  "Effect": "Allow",
  "Principal": {
    "Service": "logs.eu-west-2.amazonaws.com"
  },
  "Action": [
    "kms:Encrypt",
    "kms:Decrypt",
    "kms:ReEncrypt*",
    "kms:GenerateDataKey*",
    "kms:Describe*"
  ],
  "Resource": "*"
}
```

The service principal format is `logs.{REGION}.amazonaws.com`.

## Exam Tips
- CloudWatch Logs KMS → **CLI only, not console** ⭐
- Need to update key policy to allow `logs.{region}.amazonaws.com`
- Two CLI commands: `associate-kms-key` (existing group) vs `create-log-group --kms-key-id` (new group)
