# 30.4 — KMS Hands-On (Console + CLI)

## Console

- **AWS Managed Keys**: Found under KMS. Keys like `aws/ebs`, `aws/sqs`. Their key policy restricts access via `aws:ViaService` condition — e.g. only EC2 or SQS can use them.
- **Customer Managed Keys**: You create them. Cost $1/month.
  - Key type: Symmetric (encrypt/decrypt) or Asymmetric
  - Key origin: KMS (default), External (imported), or Custom Key Store (CloudHSM)
  - Regionality: Single region (most common) or Multi-region
  - Alias: e.g. `alias/tutorial`
  - Key Policy: Default (allows all account users via IAM) or Custom (explicit principals)
  - Key Rotation: Enable automatic rotation (90–2560 days); also supports on-demand rotation

## CLI Encrypt/Decrypt Demo

```bash
# 1. Create a file with a secret
echo "SuperSecretPassword" > ExampleSecretFile.txt

# 2. Encrypt with KMS (outputs base64)
aws kms encrypt \
  --key-id alias/tutorial \
  --plaintext fileb://ExampleSecretFile.txt \
  --query CiphertextBlob \
  --output text \
  --region eu-west-2 > ExampleSecretFileEncrypted.base64

# 3. Decode base64 to binary
base64 --decode ExampleSecretFileEncrypted.base64 > ExampleSecretFileEncrypted

# 4. Decrypt (KMS auto-detects the key used)
aws kms decrypt \
  --ciphertext-blob fileb://ExampleSecretFileEncrypted \
  --query Plaintext \
  --output text \
  --region eu-west-2 > ExampleFileDecrypted.base64

# 5. Decode base64 to get back plaintext
base64 --decode ExampleFileDecrypted.base64 > ExampleFileDecrypted.txt
# → Contains: SuperSecretPassword
```

## Key Points
- KMS automatically knows which key to use for decryption — it's embedded in the ciphertext blob
- The SDK abstracts much of this low-level work
- Encrypted value stored in code/env vars = much safer than plaintext
