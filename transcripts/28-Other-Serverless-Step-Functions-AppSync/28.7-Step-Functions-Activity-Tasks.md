# 28.7 - Step Functions - Activity Tasks

## Overview

Activity Tasks let external workers (EC2, Lambda, mobile, etc.) **poll Step Functions for work** rather than being invoked by it. The worker regularly asks "is there something for me to do?", does the work, and reports back.

---

## How It Works

1. Activity worker calls **`GetActivityTask`** API → Step Functions returns input + task token (if there's work)
2. Worker performs the task
3. Worker calls **`SendTaskSuccess(output, token)`** or **`SendTaskFailure(error, token)`** to report result

```
Activity Worker (EC2/Lambda/mobile)
        │
        │  GetActivityTask (poll)
        ▼
  Step Functions ──► returns: { input, taskToken }
        │
        │  [worker does the work]
        │
        │  SendTaskSuccess(output, taskToken)
        ▼
  Step Functions resumes execution
```

---

## Activity Tasks vs Wait For Task Token

| | Activity Tasks | waitForTaskToken |
|---|---|---|
| **Mechanism** | **Pull** — worker polls Step Functions | **Push** — Step Functions pushes to SQS/external |
| **Who initiates** | Worker calls `GetActivityTask` | Step Functions sends the message |
| **Network** | Simple — worker just needs access to Step Functions endpoint | Requires external system to reach back into Step Functions |
| **Callback API** | `SendTaskSuccess` / `SendTaskFailure` | Same: `SendTaskSuccess` / `SendTaskFailure` |

> Key difference: **pull vs push**. Activity Tasks = EC2 polls Step Functions. waitForTaskToken = Step Functions pushes event out (e.g., to SQS).

---

## Configuration Parameters

### TimeoutSeconds
- How long a task **in progress** can wait before it's considered a failure
- If the worker takes longer than this, the task fails

### HeartBeatSeconds
- The maximum time Step Functions will wait between heartbeats before considering the task dead
- The worker sends a heartbeat with the **`SendTaskHeartbeat`** API call to signal it's still alive
- Best practice: send a heartbeat at an interval shorter than `HeartBeatSeconds`
  - e.g., if `HeartBeatSeconds: 10`, send heartbeat every ~5 seconds

### Maximum wait time
- If `TimeoutSeconds` is very long AND the worker keeps sending heartbeats → task can wait **up to 1 year**

---

## Exam Tips

- ✅ Activity Tasks = **pull-based** (worker polls with `GetActivityTask`)
- ✅ waitForTaskToken = **push-based** (Step Functions pushes event out)
- ✅ Same callback APIs: `SendTaskSuccess` / `SendTaskFailure`
- ✅ `HeartBeatSeconds` — max time between heartbeats; worker uses `SendTaskHeartbeat`
- ✅ With heartbeats + long timeout → task can run up to **1 year**
- ✅ Activity workers can be EC2, Lambda, mobile devices, on-prem — anything that can poll
