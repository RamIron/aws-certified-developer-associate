# 28.8 - Step Functions - Standard vs Express

## Overview

Step Functions offers two workflow types with very different characteristics: **Standard** (default, long-running) and **Express** (short, high-volume). Express is further split into **Asynchronous** and **Synchronous**.

---

## Standard Workflows (default)

| Property | Value |
|---|---|
| Max duration | **1 year** |
| Execution model | **Exactly-once** |
| Throughput | ~2,000 executions/second |
| Execution history | Up to 90 days in console; unlimited via CloudWatch |
| Pricing | Per **state transition** |
| Use cases | Non-idempotent actions (e.g. payment processing) |

> Exactly-once = each step runs once and only once, even on retries. Safe for non-idempotent actions like payments.

---

## Express Workflows

| Property | Value |
|---|---|
| Max duration | **5 minutes** |
| Throughput | **100,000+ executions/second** |
| Execution history | CloudWatch logs only (no console history) |
| Pricing | Per execution + duration + memory consumption |
| Use cases | IoT data ingestion, streaming data, mobile app backends |

---

## Async vs Sync Express — KEY EXAM DISTINCTION

| | Async Express | Sync Express |
|---|---|---|
| **Execution model** | **At-least-once** | **At-most-once** |
| **Waits for result?** | No — fire and forget | Yes — waits for completion |
| **Results via** | CloudWatch logs | Direct response |
| **Invoked from** | Anything | API Gateway, Lambda |
| **On failure** | Step Functions can auto-retry (may run twice!) | Up to caller to retry |
| **Idempotency** | Must manage manually (same action may run twice) | Not required |
| **Use cases** | Messaging, event processing | Microservice orchestration, immediate response needed |

### Async Express — At-least-once
- Start the execution and **don't wait** for the result
- Use when you don't need an immediate response (e.g. send a message and move on)
- Because of at-least-once, the same action **may execute twice** → you must handle idempotency
- Check results in CloudWatch logs

### Sync Express — At-most-once
- Start the execution and **wait for it to complete**
- Use when you need an immediate response (e.g. orchestrate microservices and get the result)
- Can be invoked from **API Gateway** or **Lambda**
- If it fails, Step Functions does NOT retry automatically — the caller decides

---

## Summary Table

| | Standard | Express Async | Express Sync |
|---|---|---|---|
| Max duration | 1 year | 5 min | 5 min |
| Execution model | Exactly-once | At-least-once | At-most-once |
| Throughput | 2,000/s | 100,000+/s | 100,000+/s |
| Wait for result | N/A | No | Yes |
| Pricing | State transitions | Duration + memory | Duration + memory |

---

## Exam Tips

- ✅ Standard = **exactly-once**, 1 year, priced per state transition
- ✅ Express = **5 minutes**, 100,000+/s, priced per duration
- ✅ Async Express = **at-least-once** → may run twice → manage idempotency
- ✅ Sync Express = **at-most-once** → waits for result → API Gateway or Lambda invocation
- ✅ Express results only in **CloudWatch** (no console history)
- ✅ Use case keywords: payments → Standard; IoT/streaming → Express; immediate response → Sync Express
