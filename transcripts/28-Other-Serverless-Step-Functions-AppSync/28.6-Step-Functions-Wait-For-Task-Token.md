# 28.6 - Step Functions - Wait For Task Token

## Overview

`waitForTaskToken` is a Step Functions mechanism that lets a state machine **pause execution** until an external system completes its work and explicitly signals back with a task token.

---

## When to use it

Use when you need to wait for something outside Step Functions:
- Another AWS service doing async processing
- Human approval
- Third-party integration
- Legacy system call

---

## How it works

### 1. Append `.waitForTaskToken` to the resource field

```json
"Resource": "arn:aws:states:::sqs:sendMessage.waitForTaskToken"
```

This tells Step Functions: *"pause this task and wait — don't move on until someone sends back the task token."*

### 2. Pass the task token in the message

Use `$$.Task.Token` (from the context object) to inject the token into the message sent to the external system:

```json
"Parameters": {
  "QueueUrl": "https://sqs...",
  "MessageBody": {
    "Input.$": "$",
    "TaskToken.$": "$$.Task.Token"
  }
}
```

### 3. External system signals back

The receiving application (Lambda, ECS, EC2, third-party) processes the work and then calls:

- `SendTaskSuccess` → passes output + task token back to Step Functions (execution resumes)
- `SendTaskFailure` → signals failure + task token (Step Functions handles error)

---

## Full workflow example

```
Start
  │
  ▼
CheckClientCredits (Task — calls SQS with .waitForTaskToken)
  │  passes: { input, TaskToken }
  │
  ▼
[PAUSED — waiting...]
  │
  │  External app polls SQS, processes message
  │  Calls SendTaskSuccess(output, TaskToken)
  │
  ▼
Execution resumes → next state
```

---

## Key points

- The task token is **unique per task execution** — it identifies exactly which paused task to resume
- The external system can be **anything**: Lambda, ECS, EC2, on-prem, third-party
- Works with any AWS service integration that supports `.waitForTaskToken`
- This is how Step Functions integrates with **human approval flows** and **async external systems**
- If no signal is received within `TimeoutSeconds`, `States.Timeout` fires

---

## Exam Tips

- ✅ `.waitForTaskToken` appended to the Resource field → pauses execution
- ✅ Token is passed in the message body (`$$.Task.Token`)
- ✅ External system must call `SendTaskSuccess` or `SendTaskFailure` to resume
- ✅ Use case keywords: **human approval**, **external service**, **third-party**, **legacy system**
