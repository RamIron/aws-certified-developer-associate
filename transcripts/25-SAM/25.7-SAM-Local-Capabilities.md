# 25.7 - AWS SAM - Local Capabilities

**Status:** ✅ Completed

## Key Concepts

### SAM Local Commands

| Command | What it does |
|---|---|
| `sam local start-lambda` | Starts a local Lambda endpoint — run automated tests against it |
| `sam local invoke` | One-shot Lambda invocation with a payload, then quits |
| `sam local start-api` | Local HTTP server hosting all APIs + functions, hot-reloads on code change |
| `sam local generate-event` | Generates sample event payloads for any Lambda source |

### Notes
- `sam local invoke` requires `--profile` if the Lambda calls real AWS services (e.g. DynamoDB)
- `sam local start-api` auto-reloads when function code changes
- `sam local generate-event` can be piped directly into `sam local invoke`:
  ```bash
  sam local generate-event s3 put --bucket my-bucket --key my-key | sam local invoke MyFunction
  ```
- Supported event sources: S3, API Gateway, SNS, Kinesis, DynamoDB, and more

## Exam Tips
- `sam local start-lambda` = persistent local endpoint (use for automated test suites)
- `sam local invoke` = one-shot invocation (use for quick manual testing)
- `sam local generate-event` generates test payloads — can be piped into `sam local invoke`
- Always pass `--profile` when your function interacts with real AWS services
