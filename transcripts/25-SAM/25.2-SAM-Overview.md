# 25.2 - AWS SAM - Overview

**Status:** ✅ Completed

## Key Concepts

### 1. Qué es SAM
- SAM = Serverless Application Model
- Framework YAML para desarrollar y deployar aplicaciones serverless
- Genera CloudFormation por debajo (shorthand/transform)
- Requiere el header: `Transform: 'AWS::Serverless-2016-10-31'`

### 2. SAM Constructs
| SAM Resource | Genera |
|---|---|
| `AWS::Serverless::Function` | Lambda Function + IAM Role |
| `AWS::Serverless::Api` | API Gateway |
| `AWS::Serverless::SimpleTable` | DynamoDB Table |

### 3. Flujo de Deploy
```
sam build  →  sam deploy
```
- `sam build`: compila código, resuelve dependencias, empaqueta
- `sam deploy`: sube ZIP a S3, ejecuta CloudFormation changeset

### 4. SAM Accelerate (sam sync)
- Bypasses the full CloudFormation cycle for faster iteration
- Uses the service API directly (not CloudFormation)

| Command | What it does |
|---|---|
| `sam sync` | Synchronize code AND infrastructure |
| `sam sync --code` | Code changes only — bypass CloudFormation (seconds) |
| `sam sync --code --resource AWS::Serverless::Function` | Sync only all Lambda functions and their dependencies |
| `sam sync --code --resource-id HelloWorldLambdaFunction` | Sync only one specific resource by ID |
| `sam sync --watch` | Monitor for file changes, auto-sync on detection |

**`sam sync --watch` smart behavior:**
- If changes include configuration → uses `sam sync` (full infra)
- If changes are code only → uses `sam sync --code` (bypass CloudFormation)

## Exam Tips
- SAM usa CloudFormation por debajo — no es un servicio separado
- El header `Transform: 'AWS::Serverless-2016-10-31'` es obligatorio
- `sam sync --watch` es la forma más rápida de iterar en desarrollo
- `sam deploy` reemplazó a `sam package` + `sam deploy` (comando unificado)
