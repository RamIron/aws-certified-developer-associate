# 25.4 - AWS SAM - SAM with DynamoDB - Hands On

**Status:** ⏭️ Skipped (hands-on)

## What was covered

- `sam init` with a **Serverless API** template (Node.js 22) backed by DynamoDB
- SAM template structure for a multi-function API:
  - `getAllItemsFunction` → GET / → reads from DynamoDB
  - Another function → GET /{id}
  - Third function → PUT → POST method
  - `SampleTable` → `AWS::Serverless::SimpleTable` → DynamoDB with primary key + provisioned throughput
- **SAM DynamoDB CRUD Policy shorthand:**
  ```yaml
  Policies:
    - DynamoDBCrudPolicy:
        TableName: !Ref SampleTable
  ```
  SAM generates the full IAM policy from this one-liner — no raw IAM needed.

## SAM Local Commands
| Command | What it does |
|---|---|
| `sam local invoke` | Run a Lambda locally using a sample event JSON (requires Docker) |
| `sam local start-api` | Start a local API Gateway on your machine for local iteration |

- Sample events live in the `events/` folder of the project
- Local execution requires Docker — not available on CloudShell

## Cleanup
- `sam delete` — deletes the CloudFormation stack and all its resources

## Notes
- These local commands allow rapid iteration without deploying to AWS each time
- When done experimenting, always run `sam delete` to avoid charges
