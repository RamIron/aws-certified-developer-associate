# 25.6 - AWS SAM - SAM with CodeDeploy

**Status:** ✅ Completed

## Key Concepts

### 1. SAM + CodeDeploy Integration
- SAM uses CodeDeploy under the hood to update Lambda functions
- Leverages **Lambda aliases** and **traffic shifting** (same as standalone CodeDeploy)
- No need to configure CodeDeploy manually — SAM handles it via the template

### 2. Key Template Properties
```yaml
MyFunction:
  Type: AWS::Serverless::Function
  Properties:
    AutoPublishAlias: live         # Detects new code → creates new version → updates alias
    DeploymentPreference:
      Type: Canary10Percent10Minutes  # CodeDeploy deployment strategy
      Alarms:                         # Optional: CloudWatch alarms that trigger rollback
        - !Ref MyAlarm
      Hooks:                          # Optional: Lambda functions for pre/post traffic shift
        PreTraffic: !Ref PreHookFn
        PostTraffic: !Ref PostHookFn
```

### 3. AutoPublishAlias
- SAM detects when new code is deployed → creates a new Lambda version → updates the alias automatically

### 4. DeploymentPreference Types (CodeDeploy strategies)
| Type | Behavior |
|---|---|
| `Canary10Percent10Minutes` | 10% traffic to new version for 10 min, then 100% |
| `Linear10PercentEvery10Minutes` | Incremental 10% shift every 10 min |
| `AllAtOnce` | Immediate 100% switch |

### 5. Hooks (Optional)
- **PreTraffic**: Lambda runs before traffic shift — validates deployment
- **PostTraffic**: Lambda runs after full shift — runs integration tests

### 6. Automated Rollback
- CloudWatch alarms monitor the new version during traffic shift
- If alarm fires → CodeDeploy automatically rolls back to previous version

## Exam Tips
- `AutoPublishAlias` is the key SAM property that enables CodeDeploy integration
- Hooks are Lambda functions — they validate before/after traffic shifting
- CloudWatch alarms trigger automatic rollback during canary/linear deployments
- SAM creates the CodeDeployServiceRole automatically — no manual IAM setup needed
