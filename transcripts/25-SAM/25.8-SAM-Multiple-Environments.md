# 25.8 - AWS SAM - Multiple Environments

**Status:** ✅ Completed

## Key Concepts

### 1. The Problem
- You have one SAM template but need to deploy to multiple environments (dev, prod, staging...)
- Without config management, you'd pass different flags manually every time

### 2. samconfig.toml
- A TOML file that stores deployment parameters per environment
- SAM CLI reads it automatically when you pass `--config-env`

### 3. Structure
```toml
[dev.deploy.parameters]
stack_name = "my-app-dev"
s3_bucket = "my-bucket-dev"
s3_prefix = "my-app"
region = "us-east-1"
capabilities = "CAPABILITY_IAM"
parameter_overrides = "Environment=development"

[dev.sync.parameters]
stack_name = "my-app-dev"
...

[prod.deploy.parameters]
stack_name = "my-app-prod"
s3_bucket = "my-bucket-prod"
region = "us-east-1"
capabilities = "CAPABILITY_IAM"
parameter_overrides = "Environment=production"
```

### 4. Usage
```bash
sam deploy --config-env dev    # picks up [dev.deploy.parameters]
sam deploy --config-env prod   # picks up [prod.deploy.parameters]
```

## Exam Tips
- `samconfig.toml` stores per-environment parameters for SAM CLI commands
- `--config-env` flag tells SAM which environment block to read from the TOML file
- Works for both `sam deploy` and `sam sync` parameters
- You can define as many environments as needed
