SAM — Serverless Application Model SAM — Modelo de Aplicación Serverless

SAM (Serverless Application Model) is a YAML framework that lets you define serverless applications using a simplified shorthand. Under the hood it's just CloudFormation with a transform step — AWS takes your short SAM template, expands it into a full CloudFormation template, and deploys it. It is not a separate deployment service; it's a productivity layer on top of CloudFormation. SAM (Serverless Application Model) es un framework YAML que permite definir aplicaciones serverless de forma simplificada. Por debajo es simplemente CloudFormation con un paso de transformación — AWS toma tu template SAM corto, lo expande en un template de CloudFormation completo y lo deploya. No es un servicio de deploy separado; es una capa de productividad encima de CloudFormation.

Every SAM template must declare this header at the top — without it CloudFormation doesn't know to transform the AWS::Serverless::* resource types and will throw an error: Todo template SAM debe declarar este header al principio — sin él CloudFormation no sabe transformar los tipos AWS::Serverless::* y fallará:

Transform: 'AWS::Serverless-2016-10-31'

SAM provides three shorthand resource types. Each one expands into multiple CloudFormation resources automatically — IAM roles, stages, and configurations included. SAM provee tres tipos de recursos abreviados que se expanden automáticamente en múltiples recursos de CloudFormation, incluyendo roles IAM, stages y configuraciones.

Deploy Flow: sam build → sam deploy Flujo de Deploy: sam build → sam deploy

sam build runs locally — it compiles code, resolves dependencies, and produces a CloudFormation-ready artifact. sam deploy is a unified command that zips the artifact, uploads it to S3, creates a CloudFormation ChangeSet, and executes it. This replaced the old two-step sam package + sam deploy flow. sam build corre localmente — compila el código, resuelve dependencias y produce un artefacto listo para CloudFormation. sam deploy es un comando unificado que zipea el artefacto, lo sube a S3, crea un CloudFormation ChangeSet y lo ejecuta. Reemplazó el viejo flujo de dos pasos sam package + sam deploy.

SAM Accelerate — sam sync SAM Accelerate — sam sync

The problem with sam deploy: every change — even a one-liner fix — triggers the full CloudFormation cycle (minutes). SAM Accelerate bypasses CloudFormation entirely for code-only changes, pushing directly via the service API in seconds. This is a development speed tool, not for production deployments. El problema con sam deploy: cualquier cambio dispara el ciclo completo de CloudFormation (minutos). SAM Accelerate bypasea CloudFormation para cambios de código, enviándolos directo por la API del servicio en segundos. Es una herramienta de velocidad de desarrollo, no para producción.

SAM Policy Templates SAM Policy Templates

Instead of writing raw IAM roles and policies in CloudFormation, SAM provides a curated list of pre-built permission templates you attach to Lambda functions by name. SAM transforms them into proper IAM policies at deploy time. The naming is intentional — the name of the template tells you exactly what permissions it grants. En lugar de escribir roles y políticas IAM crudas en CloudFormation, SAM provee una lista de templates de permisos pre-construidos que adjuntás a funciones Lambda por nombre. SAM los transforma en políticas IAM correctas al deployar. El nombre del template te dice exactamente qué permisos otorga.

Key Policy Templates (Exam-Relevant) Policy Templates Clave (relevantes para el examen)

There are many available templates, but these three appear on the exam: Hay muchos templates disponibles, pero estos tres aparecen en el examen:

Usage in Template Uso en el Template

You reference the template by name under Policies and pass the target resource as a parameter. SAM generates the full IAM policy automatically: Referenciás el template por nombre bajo Policies y pasás el recurso objetivo como parámetro. SAM genera la política IAM completa automáticamente:

MyFunction: Type: 'AWS::Serverless::Function' Properties: CodeUri: ${codeuri} Handler: hello.handler Runtime: python2.7 Policies: - SQSPollerPolicy: QueueName: !GetAtt MyQueue.QueueName

SAM with CodeDeploy SAM con CodeDeploy

SAM natively integrates with CodeDeploy to enable safe Lambda deployments using traffic shifting. You don't configure CodeDeploy manually — SAM creates the service role and deployment group automatically. The key enabler is AutoPublishAlias: SAM detects new code, publishes a new Lambda version, and uses CodeDeploy to shift traffic from old to new gradually. SAM integra nativamente con CodeDeploy para deployos seguros de Lambda usando traffic shifting. No configurás CodeDeploy manualmente — SAM crea el service role y el deployment group automáticamente. El habilitador clave es AutoPublishAlias: SAM detecta código nuevo, publica una nueva versión de Lambda y usa CodeDeploy para cambiar el tráfico gradualmente.

Template Structure Estructura del Template

The full SAM CodeDeploy setup fits in a few lines under the function's Properties: La configuración completa de SAM + CodeDeploy cabe en pocas líneas bajo Properties de la función:

MyFunction: Type: AWS::Serverless::Function Properties: AutoPublishAlias: live # Creates version + updates alias on every deploy DeploymentPreference: Type: Canary10Percent10Minutes # Traffic shifting strategy Alarms: # CloudWatch alarms → auto rollback if triggered - !Ref AliasErrorMetricAlarm Hooks: # Optional Lambda validators PreTraffic: !Ref PreTrafficFn PostTraffic: !Ref PostTrafficFn

DeploymentPreference Types Tipos de DeploymentPreference

These map directly to CodeDeploy Lambda deployment strategies: Estos mapean directamente a las estrategias de deploy de Lambda en CodeDeploy:

Hooks & Automatic Rollback Hooks y Rollback Automático

Hooks are regular Lambda functions that run at two optional checkpoints during the deployment. If either hook returns a failure, or if a CloudWatch alarm fires during the traffic shift, CodeDeploy rolls back to the previous version automatically. Los hooks son funciones Lambda normales que corren en dos puntos opcionales durante el deploy. Si algún hook retorna falla, o si un alarm de CloudWatch se dispara durante el traffic shift, CodeDeploy hace rollback a la versión anterior automáticamente.

SAM Local Capabilities Capacidades Locales de SAM

SAM provides four CLI commands for local development and testing — letting you run and test Lambda functions on your machine without deploying to AWS. This dramatically speeds up the inner dev loop: write code, test locally, then deploy when ready. SAM provee cuatro comandos CLI para desarrollo y testing local — permitiéndote correr y probar funciones Lambda en tu máquina sin deployar a AWS. Esto acelera enormemente el ciclo de desarrollo: escribís código, probás localmente, y deployás cuando está listo.

CommandComando What it doesQué hace
sam local start-lambda Starts a persistent local Lambda endpoint — use for automated test suitesInicia un endpoint Lambda local persistente — úsalo para suites de tests automáticos
sam local invoke One-shot Lambda invocation with a payload, then quits. Use --profile if function calls real AWS servicesInvocación one-shot con payload, luego termina. Usá --profile si la función llama servicios AWS reales
sam local start-api Local HTTP server hosting all APIs + functions. Hot-reloads on code change automaticallyServidor HTTP local con todas las APIs + funciones. Hot-reload automático al cambiar código
sam local generate-event Generates sample event payloads for any Lambda source (S3, SQS, SNS, Kinesis, DynamoDB…)Genera payloads de eventos de muestra para cualquier fuente Lambda (S3, SQS, SNS, Kinesis, DynamoDB…)

Combining generate-event with invoke Combinando generate-event con invoke

You can pipe a generated event directly into sam local invoke — no need to write or store JSON payloads manually: Podés pipear un evento generado directamente a sam local invoke — sin necesidad de escribir o guardar payloads JSON a mano:

sam local generate-event s3 put --bucket my-bucket --key my-key \ | sam local invoke MyFunction

SAM — Multiple Environments SAM — Múltiples Entornos

When you need to deploy the same SAM template to multiple environments (dev, staging, prod), you create a samconfig.toml file alongside your template. It stores all deployment parameters per environment in TOML format. The SAM CLI reads the correct block automatically based on the --config-env flag you pass. Cuando necesitás deployar el mismo template SAM a múltiples entornos (dev, staging, prod), creás un archivo samconfig.toml junto a tu template. Almacena todos los parámetros de deploy por entorno en formato TOML. El SAM CLI lee el bloque correcto automáticamente según el flag --config-env que pasás.

samconfig.toml Structure Estructura de samconfig.toml

Each block follows the pattern [environment.command.parameters]. You can define as many environments as needed: Cada bloque sigue el patrón [entorno.comando.parameters]. Podés definir tantos entornos como necesités:

[dev.deploy.parameters] stack_name = "my-app-dev" s3_bucket = "my-bucket-dev" region = "us-east-1" capabilities = "CAPABILITY_IAM" parameter_overrides = "Environment=development" [prod.deploy.parameters] stack_name = "my-app-prod" s3_bucket = "my-bucket-prod" region = "us-east-1" capabilities = "CAPABILITY_IAM" parameter_overrides = "Environment=production"

Usage Uso

Pass --config-env to select the environment block. Works for both sam deploy and sam sync: Pasá --config-env para seleccionar el bloque de entorno. Funciona tanto para sam deploy como sam sync:

sam deploy --config-env dev # reads [dev.deploy.parameters] sam deploy --config-env prod # reads [prod.deploy.parameters] sam sync --config-env dev # reads [dev.sync.parameters]
