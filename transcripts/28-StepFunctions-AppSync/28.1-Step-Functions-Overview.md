# 28.1 — Step Functions Overview

## Summary
AWS Step Functions lets you model any workflow as a **state machine** defined in JSON. It orchestrates tasks (Lambda, ECS, DynamoDB, SNS/SQS, etc.) into a visual, trackable workflow. One state machine per workflow.

---

## Key Concepts

### 1. What It Is
- Workflows modeled as **state machines** (JSON definition → visual graph)
- Use cases: order fulfillment, data processing, web apps, any multi-step workflow
- Provides: visual execution, execution history, error handling
- You define what happens, what happens next, and branching conditions

### 2. How to Start a Workflow
- SDK API call
- API Gateway
- CloudWatch Events / EventBridge
- Manually from the console

### 3. Task State (core building block)
Each step in the workflow is a **task**. A task can:
- Invoke a **Lambda function**
- Run an **AWS Batch** job
- Run an **ECS task** and wait for completion
- Insert an item into **DynamoDB**
- Publish to **SNS** or **SQS**
- Launch **another Step Functions** workflow
- Run an **Activity** — an EC2/ECS/on-premises server that **polls** Step Functions for work (unlike the above, the server pulls work rather than being invoked)

### 4. Task State JSON example
```json
{
  "Invoke Lambda function": {
    "Type": "Task",
    "Resource": "arn:aws:states:::lambda:invoke",
    "Parameters": {
      "FunctionName": "my-function",
      "Payload.$": "$"
    },
    "Next": "NextStateName",
    "TimeoutSeconds": 300
  }
}
```

### 5. State Types (all 7)
| State | Purpose |
|---|---|
| **Task** | Do work (invoke Lambda, Batch, ECS, etc.) |
| **Choice** | Branch based on condition (like if/else) |
| **Fail / Succeed** | Stop execution with failure or success |
| **Pass** | Pass input to output, optionally inject fixed data |
| **Wait** | Delay for N seconds or until a specific datetime |
| **Map** | Iterate over a list, run steps for each item |
| **Parallel** | Run multiple branches simultaneously ← most exam-relevant |

---

## Exam Tips
- Step Functions = **orchestration** (not a compute service itself)
- Parallel state = run independent branches at the same time
- Activities = server **pulls** work from Step Functions (not invoked by it — similar to legacy SWF)
- Workflow defined in JSON, visualized automatically
- Can chain multiple Step Function workflows together
