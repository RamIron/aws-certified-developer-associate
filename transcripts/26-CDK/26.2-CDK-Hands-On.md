# 26.2 - AWS CDK - Hands On

**Status:** ⏭️ Skipped (hands-on)

## What was covered

- `npm install aws-cdk-lib` — install CDK globally
- `cdk init app --language javascript` — initialize a CDK app in JavaScript
- `cdk ls` — list stacks in the app (e.g. `CdkAppStack`)
- Project structure: `lib/cdk-app-stack.js` contains the stack definition

### Stack definition highlights (JavaScript)
- **S3 bucket** — `RemovalPolicy.DESTROY` so bucket is deleted with the stack
- **IAM Role** — created in code + `addToPolicy()` to attach statements programmatically
- **DynamoDB table** — partition key + removal policy defined inline
- **Lambda function** — runtime, role, env vars referencing the table and bucket defined above
- **Event source** — S3 triggers Lambda via `addEventSource()`
- **Permissions** — `bucket.grantReadWrite(fn)` and `table.grantReadWriteData(fn)` — one-liner IAM instead of manual policies

### Key CDK CLI commands
| Command | What it does |
|---|---|
| `cdk bootstrap` | One-time setup per account/region — creates CDK Toolkit CloudFormation stack (S3, IAM roles, ECR) |
| `cdk synth` | Synthesizes CDK code → CloudFormation template (preview without deploying) |
| `cdk deploy` | Deploys the synthesized CloudFormation template to AWS |
| `cdk destroy` | Destroys the CloudFormation stack and all its resources |
| `cdk ls` | Lists all stacks in the CDK app |

### Demo flow
1. Bootstrap CDK (`cdk bootstrap`) — creates CDKToolkit stack in CloudFormation
2. `cdk synth` — preview the generated CloudFormation template
3. `cdk deploy` — deploy S3 + Lambda + DynamoDB stack
4. Upload image to S3 → Lambda triggered → Rekognition detects labels → saved to DynamoDB
5. `cdk destroy` — clean up everything

## Notes
- `cdk bootstrap` only needs to run once per AWS account per region
- `cdk synth` outputs the full CloudFormation template to stdout — useful for preview/debugging
- Permissions like `grantReadWrite()` are CDK shorthand that generate correct IAM policies automatically
