CDK — Cloud Development Kit CDK — Cloud Development Kit

CDK (Cloud Development Kit) lets you define AWS infrastructure using a real programming language — TypeScript, JavaScript, Python, Java, or .NET — instead of writing YAML or JSON by hand. Under the hood it generates a CloudFormation template, so everything still deploys through CloudFormation. The key advantage over raw CloudFormation: CDK is typesafe — if your code doesn't compile, no template is generated and you catch errors before any deployment happens. CDK (Cloud Development Kit) permite definir infraestructura AWS usando un lenguaje de programación real — TypeScript, JavaScript, Python, Java o .NET — en lugar de escribir YAML o JSON a mano. Por debajo genera un template de CloudFormation, así que todo sigue deployando a través de CloudFormation. La ventaja clave sobre CloudFormation puro: CDK es typesafe — si el código no compila, no se genera template y los errores se detectan antes de cualquier deploy.

CDK Constructs CDK Constructs

Constructs are high-level reusable components — each one generates multiple underlying CloudFormation resources automatically. For example, a single ApplicationLoadBalancedFargateService construct creates the Fargate task definition, ECS service, ALB, target group, security groups, and IAM roles — all from a few lines of code. Los constructs son componentes reutilizables de alto nivel — cada uno genera múltiples recursos de CloudFormation automáticamente. Por ejemplo, un solo construct ApplicationLoadBalancedFargateService crea la task definition de Fargate, el servicio ECS, el ALB, el target group, security groups y roles IAM — todo desde pocas líneas de código.

// TypeScript example const vpc = new ec2.Vpc(this, 'MyVpc', { maxAzs: 3 }); const cluster = new ecs.Cluster(this, 'MyCluster', { vpc }); new ecs_patterns.ApplicationLoadBalancedFargateService(this, 'MyFargate', { cluster, cpu: 512, desiredCount: 6, taskImageOptions: { image: ecs.ContainerImage.fromRegistry('my-image') }, memoryLimitMiB: 2048, publicLoadBalancer: true, });

CDK vs SAM CDK vs SAM

Both generate CloudFormation under the hood, but they serve different purposes. SAM is serverless-first; CDK is a superset of CloudFormation that supports every AWS service. Ambos generan CloudFormation por debajo, pero sirven propósitos distintos. SAM es serverless-first; CDK es un superset de CloudFormation que soporta todos los servicios AWS.

CDK Constructs — L1 / L2 / L3 CDK Constructs — L1 / L2 / L3

Constructs are the building blocks of CDK — components that encapsulate everything needed to create one or more CloudFormation resources. They come from the built-in Construct Library (covers every AWS service) or from Construct Hub (third-party and open-source community constructs). There are three levels of abstraction, each progressively higher. Los Constructs son los bloques de construcción de CDK — componentes que encapsulan todo lo necesario para crear uno o más recursos de CloudFormation. Vienen de la Construct Library integrada (cubre todos los servicios AWS) o del Construct Hub (constructs de terceros y comunidad open-source). Hay tres niveles de abstracción, cada uno progresivamente más alto.

Beyond cdk synth and cdk deploy, there are a few more CLI commands worth knowing. cdk bootstrap is special — it's a one-time setup that must run before you can deploy any CDK stack to a new AWS account/region combination. Más allá de cdk synth y cdk deploy, hay otros comandos CLI importantes. cdk bootstrap es especial — es un setup único que debe correr antes de poder deployar cualquier stack CDK en una nueva combinación de cuenta/región AWS.

What is Bootstrapping? ¿Qué es el Bootstrapping?

Before deploying any CDK app to an AWS environment (account + region), you must bootstrap it. Bootstrapping creates a CloudFormation stack called CDKToolkit that contains an S3 bucket (for storing synthesized assets) and IAM roles (required for deployments). Without it, your deploy fails with: Antes de deployar cualquier app CDK a un entorno AWS (cuenta + región), debés bootstrapearlo. El bootstrapping crea un stack de CloudFormation llamado CDKToolkit que contiene un S3 bucket (para almacenar assets sintetizados) y roles IAM (necesarios para deploys). Sin él, el deploy falla con:

Error: Policy contains a statement with one or more invalid principals
cdk bootstrap aws://<account_id>/<region> # e.g. cdk bootstrap aws://123456789012/eu-west-1

CDK Unit Testing CDK Unit Testing

Because CDK uses real code, you can test your infrastructure the same way you'd test any application — with Jest (JavaScript/TypeScript) or Pytest (Python). The CDK Assertions Module lets you synthesize a stack into a CloudFormation template in memory and run assertions against it — no AWS calls, no deployment needed. Como CDK usa código real, podés testear tu infraestructura igual que cualquier aplicación — con Jest (JavaScript/TypeScript) o Pytest (Python). El CDK Assertions Module permite sintetizar un stack en un template de CloudFormation en memoria y correr assertions — sin llamadas a AWS, sin deployar.

Loading the Template Cargando el Template
