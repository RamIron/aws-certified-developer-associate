# 27.3 - Cognito User Pools - Hands On

> Hands-on lesson. Notes capture key UI concepts and configurations shown.

## Creating a User Pool

1. Console → Cognito → User Pools → **Create user pool**
2. Choose application type: Traditional web app / SPA / Mobile / M2M
3. Name the pool (e.g. "my-web-app")
4. Configure **sign-in options**: email, phone, or username

## Configuration Sections

| Section | What you configure |
|---|---|
| **Authentication** | Email/phone/username, federated IdPs (Google, Facebook, SAML, OIDC) |
| **Sign-up** | User verification (SMS/email), required attributes, custom attributes |
| **MFA** | Require / optional / disabled; SMS or authenticator app |
| **Password policy** | Minimum length, expiry, complexity requirements |
| **Passkey** | Biometric login, bypasses passwords |
| **Security** | WAF integration, threat protection, log streaming |
| **Branding / Managed Login** | Hosted UI → now called **Managed Login**; fully customizable login page |
| **Extensions** | Lambda triggers: post-signup, post-auth, custom-auth, messaging |

## Key Details

### Email verification
- CUP sends verification emails natively → **up to 50 emails/day** (for testing only)
- **Production:** use **Amazon SES** for higher volume

### Federated Identity Providers
- Set up social login (Google, Facebook, Amazon, Apple) or enterprise (SAML, OIDC) under the pool's configuration
- Each IdP has its own setup steps

### Lambda Triggers
- Can hook Lambda at various lifecycle events: post-signup, post-auth, custom auth, messaging, etc.
- Powerful way to customize Cognito behavior

### Managed Login (previously "Hosted UI")
- Auto-generated domain + login page provided by Cognito
- Custom domain supported (e.g. via Route 53)
- UI fully customizable: colors, logo, sign-in/sign-up/reset password pages

### Return URL
- After successful sign-in, user is redirected to this URL (your app's URL)

## User Lifecycle (observed in console)
1. User registers → status: **Unconfirmed**, email: **Unverified**
2. Verification code sent via email
3. User enters code → status: **Confirmed**, email: **Verified**

## Exam Notes
- 50 emails/day limit → use **SES in production**
- Lambda triggers allow deep customization of CUP flows
- Managed Login = rebranded Hosted UI (same concept)
