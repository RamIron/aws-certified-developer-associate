# 27.2 - Cognito User Pools

## What is a Cognito User Pool?
A **serverless database of users** for web and mobile applications.

## Features
- Simple login: username/email + password
- Password reset
- Email and phone number verification
- Multi-Factor Authentication (MFA)
- **Federated Identities**: login with Google, Facebook, SAML, OpenID Connect
- **Compromised credentials check**: AWS scans the web and blocks users with leaked credentials
- Returns a **JWT (JSON Web Token)** upon successful login

## How CUP Works (Diagram)
```
Mobile/Web App
      │
      │ login request
      ▼
Cognito User Pool (internal DB of users)
      │
      │ returns JWT
      ▼
Mobile/Web App
      │
      │ passes JWT
      ▼
API Gateway / ALB  ←  validates token  →  Backend
```

## Third-Party Identity Providers
- Social login: Google, Facebook, Amazon
- Enterprise: SAML, OpenID Connect

## AWS Integrations

### API Gateway
1. User authenticates with CUP → gets JWT
2. JWT passed to API Gateway
3. API Gateway validates the token
4. Allows access to backend

### Application Load Balancer
- ALB Listeners/Rules authenticate users against CUP
- After auth, forwards to Target Group (EC2, Lambda, ECS)

## Exam Tips
- CUP = serverless user DB + authentication
- Returns **JWT** (not AWS credentials — that's Identity Pools)
- Integrates natively with **API Gateway** and **ALB**
- Supports **Federated Identities** (social + enterprise logins)
