Amazon Cognito — Overview Amazon Cognito — Visión General

Amazon Cognito gives identity to the users of your web and mobile applications. These users are external — your customers, not your AWS admins. They sit outside your AWS account, and Cognito is the service that manages who they are and what they can access. Think of it as the bridge between "random people on the internet" and "authenticated users with controlled access." Amazon Cognito le da identidad a los usuarios de tus aplicaciones web y móviles. Son usuarios externos — tus clientes, no tus admins de AWS. Están fuera de tu cuenta AWS, y Cognito gestiona quiénes son y a qué pueden acceder. Es el puente entre "gente random de internet" y "usuarios autenticados con acceso controlado."

Cognito User Pools (CUP) Cognito User Pools (CUP)

A Cognito User Pool is a serverless user database + authentication system for your app. AWS handles sign-up, sign-in, password reset, MFA, and email/phone verification out of the box. On successful login, CUP returns a JWT (JSON Web Token) — not AWS credentials. That distinction is an exam favourite. Un Cognito User Pool es una base de datos de usuarios serverless + sistema de autenticación para tu app. AWS gestiona sign-up, sign-in, reset de contraseña, MFA y verificación de email/teléfono out of the box. Tras el login, CUP retorna un JWT (JSON Web Token) — no credenciales AWS. Esa distinción es favorita del examen.

Integration with API Gateway Integración con API Gateway

CUP integrates natively with API Gateway. The client logs in, gets a JWT, then sends it with every API request. API Gateway calls Cognito to validate the token before forwarding to the backend — no custom validation code needed. CUP se integra nativamente con API Gateway. El cliente se loguea, obtiene un JWT y lo envía con cada request. API Gateway llama a Cognito para validar el token antes de hacer forward al backend — sin código de validación custom.

Integration with Application Load Balancer Integración con Application Load Balancer

The ALB can handle the full authentication flow before traffic reaches your backend. It redirects the user to the CUP login page, receives the token, then forwards only authenticated requests to your target — EC2, ECS, or Lambda. El ALB puede manejar el flujo completo de autenticación antes de que el tráfico llegue al backend. Redirige al usuario a la página de login de CUP, recibe el token, y luego hace forward solo de los requests autenticados al target — EC2, ECS o Lambda.

Cognito User Pools can be extended through Lambda triggers — hooks invoked synchronously at specific points in the user lifecycle. This allows custom validation, token modification, user migration, and message customization without replacing CUP with a custom auth system. Los Cognito User Pools se pueden extender a través de Lambda triggers — hooks invocados sincrónicamente en puntos específicos del ciclo de vida del usuario. Permiten validación custom, modificación de tokens, migración de usuarios y personalización de mensajes sin reemplazar CUP.

Adaptive Authentication Autenticación Adaptativa

CUP assigns a risk score (low / medium / high) to each sign-in based on device, location, and IP. High-risk logins trigger MFA challenges automatically. All activity is logged to CloudWatch Logs. CUP asigna un risk score (bajo / medio / alto) a cada sign-in según dispositivo, ubicación e IP. Logins de alto riesgo activan MFA automáticamente. Toda la actividad se loguea en CloudWatch Logs.

Pre Token Generation is the trigger to customize JWT claims. Post Confirmation is the trigger for welcome emails after sign-up. Pre Token Generation es el trigger para customizar claims del JWT. Post Confirmation es el trigger para emails de bienvenida tras el sign-up.

JWT Token Structure Estructura del JWT Token

A Cognito JWT has three Base64-encoded sections separated by dots: header.payload.signature. Always verify the signature before trusting any payload claims. The key field for identifying a user in your own database is sub — a permanent UUID that never changes, unlike username. Un JWT de Cognito tiene tres secciones codificadas en Base64 separadas por puntos: header.payload.signature. Siempre verificar la firma antes de confiar en los claims del payload. El campo clave para identificar a un usuario en tu propia base de datos es sub — un UUID permanente que nunca cambia, a diferencia de username.

ALB — User Authentication ALB — Autenticación de Usuarios

The Application Load Balancer can authenticate users before requests reach your backend, offloading auth logic from your application entirely. Two options are supported: Cognito User Pools or any OIDC-compliant identity provider. The listener must be HTTPS for either option. El ALB puede autenticar usuarios antes de que los requests lleguen al backend, delegando la lógica de auth fuera de la aplicación. Se soportan dos opciones: Cognito User Pools o cualquier proveedor OIDC. El listener debe ser HTTPS en ambos casos.

Cognito Identity Pools (Federated Identities) Cognito Identity Pools (Identidades Federadas)

Cognito Identity Pools solve a different problem than User Pools: your external users need to call AWS services directly (S3, DynamoDB) but you can't create IAM users for millions of customers. Identity Pools act as a credential vending machine — a user proves their identity via any supported login provider, and in return gets temporary AWS credentials they can use with the SDK. No JWT is returned here; real AWS credentials come out via STS. Cognito Identity Pools resuelven un problema distinto al de User Pools: los usuarios externos necesitan llamar a servicios AWS directamente (S3, DynamoDB) pero no puedes crear usuarios IAM para millones de clientes. Los Identity Pools actúan como una máquina expendedora de credenciales — el usuario prueba su identidad con cualquier proveedor soportado y recibe credenciales AWS temporales via STS.
