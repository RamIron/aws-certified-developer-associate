# 27.5 - Application Load Balancer - User Authentication

## Overview
The ALB can authenticate users before requests reach your application, offloading auth responsibility from the app entirely.

## Two Authentication Options

| Option | How it works |
|---|---|
| **OIDC-compliant IdP** | Integrate directly with any OpenID Connect provider (no Cognito needed) |
| **Cognito User Pools** | For social login (Google, Facebook, Amazon) or corporate (SAML, LDAP, Microsoft AD) |

## Requirements
- Listener must be **HTTPS** (not HTTP)
- ALB rule action: `authenticate-oidc` or `authenticate-cognito`

## Unauthenticated Request Behavior
Three options when a user is not authenticated:
1. **Authenticate** (default) — redirect to login
2. **Deny** — return 401/403
3. **Allow** — pass through without auth (useful for public pages like `/login`)

## Flow: ALB + Cognito User Pool
```
User → GET /api/data → ALB (HTTPS, authenticate-cognito action)
                         → Cognito authenticates user
                         → Request forwarded to ECS with user info added
                         ← Response with user-specific data
```
ALB adds user claims/info to the request headers so your backend knows who the user is.

## Flow: ALB + OIDC Provider (no Cognito)
More steps, but works with any OIDC-compliant IdP:

1. User → HTTP request → ALB
2. ALB redirects user to IdP **authorization endpoint**
3. IdP returns **authorization code** to ALB
4. ALB sends code to IdP **token endpoint** → gets ID token + access token
5. ALB sends access token to IdP **user info endpoint** → gets user claims
6. ALB forwards original request + user claims to backend

## OIDC Setup Requirements
- Authorization endpoint
- Token endpoint
- User info endpoint
- Client ID + Client Secret
- Proper redirect/callback URLs configured

## Key Takeaway
- **Cognito option**: simpler setup, great for social/enterprise logins
- **OIDC option**: more flexible, more configuration, works with any OIDC IdP
- Both add user info to forwarded requests so your backend can use it

## Exam Tips
- ALB auth requires **HTTPS listener**
- `authenticate-cognito` or `authenticate-oidc` are the rule actions
- Unauthenticated behavior: authenticate / deny / allow
- OIDC flow involves 3 IdP endpoints: authorization, token, user info
