# 27.7 — Cognito Identity Pools — Hands On

## Summary
Console walkthrough creating a Cognito Identity Pool connected to an existing Cognito User Pool. Covers the two access types, IAM role creation, and role mapping options.

---

## Key Steps in the Console

### 1. Create an Identity Pool
- Navigate to **Cognito → Identity Pools → Create identity pool**
- Choose access type(s):
  - **Authenticated access** — requires defining an identity source
  - **Guest access** — unauthenticated users; can be enabled alongside authenticated

### 2. Configure Authenticated Identity Source
- Choose from: Amazon Cognito User Pool, Facebook, Google, Apple, Amazon, Twitter, OIDC, SAML, or Custom Developer Provider
- If using CUP: supply the **Pool ID** and **App Client ID** (from the User Pool created previously)

### 3. Assign IAM Roles
- **Authenticated role** — assumed by logged-in users; contains permissions for what they can do in AWS
- **Guest role** (unauthenticated) — assumed by anonymous users; should be minimal/restricted
- Both roles start with minimal policy and are customized afterwards via IAM

### 4. Role Mapping Options
- **Default authenticated role** — all authenticated users get the same role (simple)
- **Role with rules** — route different users to different roles based on token claims
- **Attributes for access control** — map token attributes (e.g. username, client) into IAM policy variables for fine-grained control

### 5. After Creation — IAM Integration
- After creating the pool, go to **IAM → Roles** and search "Cognito"
- The two roles (authenticated + unauthenticated) appear there
- Add inline policies or attach managed policies to grant actual AWS permissions (e.g., S3 read, DynamoDB access)

---

## Exam Notes
- The Identity Pool itself doesn't contain user data — it just brokers credentials
- Role assignment happens at the Identity Pool level; permissions are defined in IAM
- Fine-grained access (per-user prefix, row-level) is set via IAM policy variables on the role
- You can mix CUP + social providers as sources in the same identity pool
