Policy Inheritance — Weak PointHerencia de Políticas — Punto Débil

🔴 Weak point area: Understand how policies stack.Área de punto débil: Entiende cómo se apilan las políticas.
  • Group policy — attached to a group; all users in that group inherit it automatically.Política de grupo — vinculada a un grupo; todos los usuarios en ese grupo la heredan automáticamente.
  • Inline policy — attached directly to a single user; applies only to that user.Política inline — vinculada directamente a un solo usuario; se aplica solo a ese usuario.
  • Both apply simultaneously — a user's effective permissions = all group policies + all inline policies combined.Ambas se aplican simultáneamente — los permisos efectivos de un usuario = todas las políticas de grupo + todas las políticas inline combinadas.
  • Deny overrides Allow — an explicit Deny anywhere will block the action, even if another policy Allows it.Deny anula Allow — un Deny explícito en cualquier lugar bloqueará la acción, incluso si otra política la Permite.
Best practice: Assign permissions via groups, not individual users. Inline policies are exceptions — use them sparingly. Apply the least privilege principle: grant only what is needed.Buena práctica: Asigna permisos a través de grupos, no a usuarios individuales. Las políticas inline son excepciones — úsalas con moderación. Aplica el principio de mínimo privilegio: otorga solo lo necesario.

IAM RolesRoles de IAM

Roles are like users, but designed for AWS services — not people. When a service assumes a role, AWS provides temporary credentials automatically. No access keys needed (or allowed).Los roles son como usuarios, pero diseñados para servicios de AWS — no para personas. Cuando un servicio asume un rol, AWS proporciona credenciales temporales automáticamente. No se necesitan claves de acceso (ni se permiten).

🖥

EC2 Instance RoleRol de Instancia EC2

Allows EC2 instances to call AWS APIs (e.g., read from S3, write to DynamoDB) without storing credentials on the instance.Permite que las instancias EC2 llamen a las APIs de AWS (p. ej., leer de S3, escribir en DynamoDB) sin almacenar credenciales en la instancia.

λ

Lambda Function RoleRol de Función Lambda

Lambda automatically assumes an execution role on invocation. Defines what AWS services the Lambda function is allowed to call.Lambda asume automáticamente un rol de ejecución en la invocación. Define qué servicios de AWS puede llamar la función Lambda.

🏗

CloudFormation RoleRol de CloudFormation

Grants CloudFormation permission to create, update, or delete AWS resources on your behalf when deploying stacks.Otorga permiso a CloudFormation para crear, actualizar o eliminar recursos de AWS en tu nombre al desplegar pilas.

🔄

Cross-Account RoleRol de Cuenta Cruzada

Allows principals in one AWS account to assume a role in another account, providing controlled cross-account access without sharing credentials.Permite que los principios en una cuenta de AWS asuman un rol en otra cuenta, proporcionando acceso controlado entre cuentas sin compartir credenciales.

🚨 NEVER put access keys on an EC2 instance. If the instance is compromised, those keys are compromised. Use an IAM Role instead — EC2 gets temporary, automatically rotating credentials with no manual key management.NUNCA pongas claves de acceso en una instancia EC2. Si la instancia se ve comprometida, esas claves se ven comprometidas. Usa un Rol de IAM en su lugar — EC2 obtiene credenciales temporales que rotan automáticamente sin gestión manual de claves.

IAM Complete Glossary — Every "Thing" AWS Invented Glosario Completo de IAM — Cada "cosa" que inventó AWS

IAM has many overlapping concepts that are easy to confuse on the exam. This card defines each one in one line.IAM tiene muchos conceptos que se superponen y se confunden en el examen. Esta card define cada uno en una línea.

Identities (who acts)Identidades (quién actúa)

AWS officially classifies Users, Groups, and Roles as IAM identities. However, Groups are a special case: they cannot act on their own (no API calls, no role assumption) — they only exist to assign policies to Users in bulk. The exam sometimes treats "identity" as Users + Groups + Roles, and sometimes as Users + Roles only, depending on context.AWS clasifica oficialmente a Users, Groups y Roles como identidades IAM. Sin embargo, Groups son un caso especial: no pueden actuar por sí solos (sin llamadas API, sin asumir roles) — solo existen para asignar policies a Users en masa. El examen a veces trata "identity" como Users + Groups + Roles, y a veces como Users + Roles, dependiendo del contexto.

Tricky Quiz Questions Preguntas Tricky del Quiz

Q: Which is the only resource-based policy that the IAM service supports? P: ¿Cuál es la única policy basada en recursos que soporta el servicio IAM?

✅ Answer: Trust Policy✅ Respuesta: Trust Policy

Why not the others? ACL → resource-based but belongs to S3/VPC, not IAM. SCP → AWS Organizations, not IAM, limits entire accounts. Permissions Boundary → attaches to a User or Role (identity-based), defines max permissions but does NOT grant them. Trust Policy is the one policy that lives on a Role as a resource and defines who can assume it. ¿Por qué no las otras? ACL → basada en recursos pero pertenece a S3/VPC, no a IAM. SCP → es de AWS Organizations, no de IAM, limita cuentas enteras. Permissions Boundary → se adjunta a un User o Role (identity-based), define permisos máximos pero NO los otorga. La Trust Policy es la única que vive en un Role como recurso y define quién puede asumirlo.
