# 23.19 - API Gateway REST API vs HTTP API

**Section:** 23 - AWS Serverless: API Gateway

---

## Comparison Table

| Feature | REST API | HTTP API |
|---------|----------|----------|
| **Cost** | Higher | **Much cheaper** |
| **Latency** | Standard | Lower |
| **Data mapping / Mapping templates** | ✅ Yes | ❌ No (proxy only) |
| **Usage Plans & API Keys** | ✅ Yes | ❌ No |
| **Resource Policies** | ✅ Yes | ❌ No |
| **CORS** | Manual | ✅ Built-in |
| **Authorization** | IAM, Cognito, Lambda Authorizer | OIDC, OAuth 2.0 only |
| **Native OpenID Connect / OAuth 2.0** | ❌ No | ✅ Yes |
| **Private integration** | ✅ Yes | ✅ Yes |

---

## Key Takeaway for the Exam

- **HTTP API** = simpler, cheaper, proxy-only, limited auth options
- **REST API** = full feature set (everything covered in this section)
- If a question asks about **resource policies, usage plans, API keys, or mapping templates** → **REST API**
- If a question asks about the **cheapest/simplest** option → **HTTP API**

---

## WebSocket API (brief mention)

- May appear on the exam at a high level

---

## Exam Tips

- HTTP APIs are **cheaper** but **no mapping templates, no usage plans, no API keys, no resource policies**
- REST APIs support **everything** except native OpenID Connect / OAuth 2.0
- HTTP APIs have **built-in CORS** support
- HTTP APIs support **OIDC and OAuth 2.0** natively (REST APIs don't)
