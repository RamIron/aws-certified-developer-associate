**Section:** 23 - AWS Serverless: API Gateway

## API Gateway as a Microservices Facade

API Gateway can act as a **single unified URL** for all your microservices, hiding backend complexity from clients.

```
                        /service1 → ELB → ECS cluster
Client → API Gateway →  /docs     → S3 bucket (static content)
                        /service2 → ELB → EC2 Auto Scaling group
```

---

## What API Gateway Adds at the Architecture Level

- **Single URL** for all microservices
- **Custom domains** via Route 53 (e.g. customer1.example.com, customer2.example.com)
- **SSL certificates** per domain
- **Forwarding & transformation rules** — modify data before it hits backends
- **Hides complexity** — clients don't need to know about the internal routing

---

## Key Takeaway

API Gateway is not just for Lambda. It can sit in front of **any backend** (ECS, EC2, S3, ELB) and act as the unified API layer for your entire architecture.
