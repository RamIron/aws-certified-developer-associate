# 23.8 - API Gateway Canary Deployments Hands On

**Section:** 23 - AWS Serverless: API Gateway
**Type:** Hands-on (skipped quiz) — key steps noted

---

## Canary Deployment Workflow (Step by Step)

1. **Create/deploy** your API to a stage (e.g. "canary" stage pointing to Lambda v1)
2. **Create a canary** on that stage → set traffic split % (e.g. 50/50 for demo, 10% in practice)
3. **Modify** your API resource to point to the new version (e.g. Lambda v2)
4. **Deploy to canary** (not to the main stage) → only the canary channel gets the new version
5. **Monitor** — canary traffic hits v2, main stage traffic still hits v1
6. **Promote** the canary → 100% of traffic moves to v2, canary is dissolved

---

## Key Detail: Pointing to a Specific Lambda Version

To invoke a specific Lambda version directly from API Gateway (without an alias), append `:version` to the function ARN:

```
myFunction:1   → invokes version 1
myFunction:2   → invokes version 2
```

---

## Exam Tips

- Deploy changes to **canary first**, not directly to the stage
- Promote canary = makes the new version live for 100% of traffic
- Traffic split is configurable (typically a small %, e.g. 5-10% in prod)
