# 23.7 - API Gateway Canary Deployments

**Section:** 23 - AWS Serverless: API Gateway

---

## What is a Canary Deployment?

A way to test a new version of your API on a **small percentage of real production traffic** before fully rolling it out.

```
                        95% → prod stage (v1)  → existing backend
Client → prod stage →
                         5% → canary channel (v2) → new backend
```

---

## How it Works in API Gateway

- Enabled on a **production stage**
- You choose the **% of traffic** routed to the canary channel
- Canary has **separate metrics and logs** from the main stage → better monitoring/debugging
- You can **override stage variables** for the canary channel
- When confident → promote canary to 100% (replaces the main stage)
- If something goes wrong → roll back to 0% instantly

---

## Key Equivalence

> Canary deployment on API Gateway + Lambda = **Blue/Green deployment**

---

## Exam Tips

- Canary = test new API version on a % of prod traffic
- Metrics and logs are **separate** for canary vs main stage
- Can override stage variables on the canary channel
- Equivalent to blue/green deployment
- Always done on an **existing stage** (typically prod)
