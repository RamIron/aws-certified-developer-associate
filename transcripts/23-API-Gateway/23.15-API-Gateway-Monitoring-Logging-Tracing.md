# 23.15 - API Gateway Monitoring, Logging and Tracing

**Section:** 23 - AWS Serverless: API Gateway

---

## CloudWatch Logs

- Enabled at the **stage level**
- Logs request and response body going through API GW
- Log levels: **ERROR**, **INFO**, **DEBUG** (debug = most verbose)
- Can be overridden per API/method
- ⚠️ Be careful — may log **sensitive data**

```
Client → API GW → [logged to CW] → Backend
Client ← API GW ← [logged to CW] ← Backend
```

---

## X-Ray

- Enables **distributed tracing** across API GW + Lambda
- API GW + Lambda both enabled → **full picture** of a request end to end

---

## CloudWatch Metrics (per stage)

| Metric | What it measures |
|--------|-----------------|
| **CacheHitCount** | Requests served from cache |
| **CacheMissCount** | Requests that missed cache → went to backend |
| **Count** | Total number of API requests in a period |
| **IntegrationLatency** | Time API GW waits for backend response |
| **Latency** | Total time from client request to client response (includes IntegrationLatency + API GW processing) |
| **4XXError** | Client-side errors |
| **5XXError** | Server-side (backend) errors |

> **Latency > IntegrationLatency** always — Latency includes auth checks, caching, mapping templates, etc.
> Max Latency = **29 seconds** → anything above = timeout (504)

---

## Throttling

- **Default account limit:** 10,000 req/sec across ALL APIs (soft limit — can be increased)
- If one API is overloaded → can throttle **other APIs** in the account (just like Lambda concurrency)
- Throttled requests return: **429 Too Many Requests**
- Clients should retry with **exponential backoff**

### How to protect individual APIs:
- Set **stage-level limits** — cap one stage's usage
- Set **method-level limits** — cap individual methods
- Use **usage plans** — throttle per customer/API key

---

## Error Codes Reference

| Code | Type | Meaning |
|------|------|---------|
| 400 | 4XX Client | Bad Request |
| 403 | 4XX Client | Access Denied / WAF blocked |
| 429 | 4XX Client | Too Many Requests (throttling) |
| 502 | 5XX Server | Bad Gateway — Lambda proxy returned invalid response |
| 503 | 5XX Server | Service Unavailable — backend unavailable |
| 504 | 5XX Server | Integration Failure — timeout (29s exceeded) |

---

## Exam Tips

- CloudWatch Logs → log level at stage level, can override per method
- X-Ray + API GW + Lambda = full distributed tracing
- **IntegrationLatency** = backend time only; **Latency** = total round trip
- 10,000 req/s default account limit (soft) → overloaded API throttles others
- **429** = throttling (client error); **504** = timeout after 29s (server error)
- Retry throttled requests with **exponential backoff**
