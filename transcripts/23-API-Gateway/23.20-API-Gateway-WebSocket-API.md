# 23.20 - API Gateway WebSocket API

**Section:** 23 - AWS Serverless: API Gateway

---

## What is WebSocket?

- **Two-way, persistent** communication between client and server
- Server can **push data to the client** without the client making a request first
- Enables **stateful** applications
- Use cases: chat apps, collaboration platforms, multiplayer games, financial trading

---

## Connection Lifecycle

WebSocket URL format:
```
wss://{unique-id}.execute-api.{region}.amazonaws.com/{stage}
```

```
Client connects    → onConnect Lambda invoked    → connectionId persisted (e.g. DynamoDB)
Client sends data  → sendMessage Lambda invoked  → connectionId remains the same
Client disconnects → onDisconnect Lambda invoked
```

- The **connectionId** is stable for the entire duration of the connection
- Lambda functions can use the connectionId to retrieve user metadata from DynamoDB

---

## Server → Client Communication (Connection URL Callback)

To push data back to a client, any backend (Lambda, etc.) makes an HTTP request to:

```
https://{unique-id}.execute-api.{region}.amazonaws.com/{stage}/@connections/{connectionId}
```

| Operation | HTTP Method | What it does |
|-----------|-------------|-------------|
| Send message to client | **POST** | Pushes data to the connected client |
| Get connection status | **GET** | Checks if client is still connected |
| Disconnect client | **DELETE** | Forcibly disconnects the client |

- Must be signed with **IAM Sig v4**

---

## WebSocket Routing

Incoming JSON messages are routed to different backends based on a **route selection expression**.

**Built-in routes (mandatory):**
- `$connect` — client connects
- `$disconnect` — client disconnects
- `$default` — no matching route found

**Custom routes:** defined by you (e.g. join, quit, delete)

**Example:**
```json
{ "service": "chat", "action": "join", "data": { "room": "room1234" } }
```
Route selection expression: `$request.body.action`
→ evaluates to `"join"` → routed to the `join` backend

If no route matches → goes to `$default`.

---

## Exam Tips

- WebSocket = **two-way communication**, server can push to client
- Connection URL = `wss://...` ; Callback URL = `https://.../@connections/{connectionId}`
- connectionId is **stable** for the life of the connection
- POST to callback URL = send message to client; DELETE = disconnect client
- Routing based on **route selection expression** applied to incoming JSON
- `$connect`, `$disconnect`, `$default` are the 3 mandatory routes
