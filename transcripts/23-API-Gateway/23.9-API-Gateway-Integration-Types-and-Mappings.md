# 23.9 - API Gateway Integration Types & Mappings

**Section:** 23 - AWS Serverless: API Gateway

---

## Integration Types Overview

| Type | Proxy? | Mapping Templates? | Use Case |
|------|--------|-------------------|----------|
| **MOCK** | No | No | Return a fixed response without hitting any backend. Dev/testing only. |
| **HTTP** | No | ✅ Yes | Forward to HTTP backend WITH ability to modify request/response |
| **AWS** | No | ✅ Yes | Forward to AWS service WITH ability to modify request/response |
| **AWS_PROXY (Lambda Proxy)** | ✅ Yes | No | Pass full request to Lambda as-is. Lambda handles everything. |
| **HTTP_PROXY** | ✅ Yes | No | Pass full request to HTTP backend as-is. Can add HTTP headers (e.g. API key). |

---

## Proxy vs Non-Proxy

### Proxy (AWS_PROXY / HTTP_PROXY)
- Request is passed **as-is** to the backend
- **No mapping templates** — cannot modify request or response
- Lambda receives the full event object (resource, path, method, headers, queryStringParameters, body, stageVariables, etc.)
- Lambda is **fully responsible** for building the response (statusCode, headers, body)

### Non-Proxy (HTTP / AWS)
- Must configure **integration request** AND **integration response**
- **Mapping templates** can modify the request before sending and the response before returning
- API Gateway has the power to transform data between client and backend

---

## Mapping Templates

- Only applicable for **HTTP** and **AWS** integrations (non-proxy)
- Written in **VTL (Velocity Template Language)** — supports for loops, if statements, etc.
- Content-Type must be set to `application/json` or `application/xml`

### What you can do with Mapping Templates:
- Rename or modify query string parameters
- Modify the body content
- Add or modify headers
- Filter/remove fields from the response

---

## Exam Use Cases

### 1. REST → SOAP (classic exam scenario)
```
Client (JSON) → API GW → [mapping template: JSON→XML] → SOAP backend
SOAP backend (XML) → [mapping template: XML→JSON] → Client (JSON)
```
- API Gateway extracts data from the request
- Mapping template builds the SOAP XML message
- Transforms XML response back to JSON for the client

### 2. Rename Query String Parameters
```
Client: GET /resource?name=foo&other=bar
                ↓ mapping template
Lambda receives: { "myVariable": "foo", "otherVariable": "bar" }
```
- Useful when your Lambda expects different parameter names than what clients send

---

## Exam Tips

- **MOCK** = no backend, just a fixed response (dev/testing only)
- **Proxy integrations** = no mapping templates, backend does all the work
- **Non-proxy integrations** = mapping templates available
- Mapping templates use **VTL (Velocity Template Language)**
- Content-Type must be `application/json` or `application/xml` to use mapping templates
- REST→SOAP conversion via mapping templates is a classic exam scenario
- HTTP_PROXY can add secret HTTP headers (e.g. API keys) that clients don't see
