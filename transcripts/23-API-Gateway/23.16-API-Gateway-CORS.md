# 23.16 - API Gateway CORS

**Section:** 23 - AWS Serverless: API Gateway

---

## What is CORS?

CORS (Cross-Origin Resource Sharing) is a browser security mechanism that blocks requests made from one domain to another unless the server explicitly allows it.

---

## When You Need It

Enable CORS on API Gateway when your frontend (on one domain) makes API calls to API Gateway (on a different domain):

```
Browser → S3 static website (www.example.com)
              ↓ JavaScript tries to call
          API Gateway (api.example.com)  ← different origin!
              ↓ browser blocks unless CORS is enabled
```

---

## How It Works

1. Browser sends an **OPTIONS pre-flight request** to API Gateway
2. API Gateway responds with CORS headers (if origin is allowed):
   - `Access-Control-Allow-Methods`
   - `Access-Control-Allow-Headers`
   - `Access-Control-Allow-Origin`
3. If pre-flight passes → browser proceeds with the actual request

---

## How to Enable

Can be enabled directly from the **API Gateway console** on any resource.

---

## Exam Tips

- CORS must be enabled for **cross-origin** API calls from a browser
- Works via **OPTIONS pre-flight request**
- Key headers: `Access-Control-Allow-Methods`, `Access-Control-Allow-Headers`, `Access-Control-Allow-Origin`
- Common scenario: S3-hosted frontend calling API Gateway
