Only for HTTP/AWS (non-proxy). Written in VTL (Velocity Template Language). Content-Type must be application/json or application/xml.Solo para HTTP/AWS (sin proxy). Escritos en VTL. Content-Type: application/json o application/xml.

Usage Plans, API Keys & MonitoringUsage Plans, API Keys y Monitoreo

API key sent via x-api-key header. Usage plan sets throttle (req/sec) + quota (req/period) per key.API key enviada via header x-api-key. Usage plan define throttle + quota por key.

🚨 Setup order: 1) Create API + require key on methods + deploy → 2) Generate API keys → 3) Create usage plan → 4) Associate stages + keys to usage plan ← easy to forget!Orden de setup: 1) API → 2) Keys → 3) Usage plan → 4) Asociar stages + keys ← ¡fácil de olvidar!

Authentication & AuthorizationAutenticación y Autorización

Method 1 — IAM Authorization + Sig v4

Best for: internal AWS resources (EC2, Lambda, IAM users). Uses Signature v4.Mejor para: recursos internos de AWS (EC2, Lambda, usuarios IAM). Usa Signature v4.

Method 2 — Cognito User Pools

Best for: external users (mobile/web). No custom auth code. API GW validates token natively with Cognito.Mejor para: usuarios externos (mobile/web). Sin código de auth custom. API GW valida el token directamente con Cognito.

Note: Authorization logic still lives in the backend Lambda function.Nota: La lógica de autorización sigue en el Lambda del backend.

Method 3 — Lambda Authorizer (Custom Authorizer)

Best for: 3rd party auth systems (Auth0, OAuth, JWT). Most flexible, most work. Returns IAM policy (cached).Mejor para: sistemas de auth de terceros (Auth0, OAuth, JWT). Más flexible, más trabajo. Retorna IAM policy (cacheada).

⚠️ Result is cached, but you still pay per Lambda Authorizer invocation.El resultado se cachea, pero aún pagás por cada invocación del Lambda Authorizer.
