# 21.34 - Lambda Concurrency

> **Lecture 297** | Section 21: AWS Serverless: Lambda
> How Lambda scales, concurrency limits, throttling, and provisioned concurrency for cold starts

---

## Concurrency Basics

- Lambda scales automatically — more invocations = more concurrent executions
- **Account concurrency limit:** up to 1,000 concurrent executions (across ALL functions)
  - **Note:** New accounts may start lower (e.g., 50). AWS **raises quotas automatically** based on usage, or you can **request a quota increase**
- You can set **Reserved Concurrency** at the function level to limit a specific function

```
  Account Concurrency Pool: 1,000
  ┌──────────────────────────────────────────────┐
  │████████████████████████████████░░░░░░░░░░░░░░│
  │  Function A: 600    Function B: 200   Free: 200
  └──────────────────────────────────────────────┘
```

---

## Throttling Behavior

When concurrency limit is exceeded:

| Invocation Type | Throttle Behavior |
|-----------------|-------------------|
| **Synchronous** | Returns **429 ThrottleError** (callers like API Gateway may return **502** to end users) |
| **Asynchronous** | Retries automatically, then → **DLQ** |

> If you see **429** or **502/500 errors** related to Lambda → think **throttling / concurrency limits**

---

## The Danger of No Reserved Concurrency

Without reserved concurrency, **one function can consume all 1,000** and throttle everything else:

```
  BEFORE (low traffic — everything fine)
  ┌──────────────────────────────────────────────┐
  │██ ALB→Lambda    ██ API GW→Lambda   █ SDK/CLI │
  │  (50)            (30)              (10)      │
  │                                    Free: 910 │
  └──────────────────────────────────────────────┘

  AFTER (promotion! ALB gets hammered)
  ┌──────────────────────────────────────────────┐
  │██████████████████████████████████████████████│
  │  ALB→Lambda: 1,000                           │
  │  API GW→Lambda: THROTTLED ❌                  │
  │  SDK/CLI: THROTTLED ❌                        │
  └──────────────────────────────────────────────┘

  ⚠ Concurrency limit is ACCOUNT-WIDE!
    One function hogging = other functions throttled
```

> **Exam tip:** If one Lambda function is throttling others → set **Reserved Concurrency** on the high-traffic function to limit it

## Async Invocations + Throttling

When async invocations (e.g., S3 events) are throttled:

```
  S3 bucket                Lambda
    │                        │
    │──event──event──event──►│
    │                        │ Can't scale (limit reached)
    │                        │
    │              ┌─────────┴─────────┐
    │              │  Internal Event    │
    │              │  Queue             │
    │              │                    │
    │              │  Retries for up    │
    │              │  to 6 HOURS        │
    │              │                    │
    │              │  Exponential       │
    │              │  backoff:          │
    │              │  1s → ... → 5 min  │
    │              └────────────────────┘
```

- Throttled async events return to the **internal event queue**
- Retries for up to **6 hours**
- Retry interval: **exponential backoff** from 1 second up to max 5 minutes

## Cold Starts & Provisioned Concurrency

### Cold Start Problem
- New Lambda instance = code loaded + init code runs (outside handler)
- Heavy init (many dependencies, DB connections) = **high latency on first request**
- Users experience slow first response

### Solution: Provisioned Concurrency
- Allocate concurrency **before** the function is invoked
- Instances are pre-initialized → **cold start never happens**
- All invocations have **low latency**
- Manage with **Application Auto Scaling** (schedule or target tracking)

```
  WITHOUT Provisioned Concurrency:
  ┌───────┐
  │ Req 1 │ ████████████████░░░░  (INIT + handler = slow)
  │ Req 2 │ ░░░░░░░░░░           (reused = fast)
  │ Req 3 │ ░░░░░░░░░░           (reused = fast)
  └───────┘

  WITH Provisioned Concurrency:
  ┌───────┐
  │ Req 1 │ ░░░░░░░░░░           (pre-warmed = fast!)
  │ Req 2 │ ░░░░░░░░░░           (pre-warmed = fast!)
  │ Req 3 │ ░░░░░░░░░░           (pre-warmed = fast!)
  └───────┘
```

> **Note:** VPC cold starts have been dramatically reduced since Oct/Nov 2019 AWS improvements

## Exam Tips

- **Account-wide limit:** 1,000 concurrent executions (default)
- **Reserved Concurrency** = limit per function → prevents one function from starving others
- Sync throttle = **429 error** | Async throttle = **retry + DLQ**
- Async retries: up to **6 hours**, **exponential backoff** (1s → 5 min max)
- **Cold start** = first invocation latency (init code runs)
- **Provisioned Concurrency** = pre-warm instances → no cold start
- Manage provisioned concurrency with **Application Auto Scaling**
- Need more than 1,000? → **support ticket**
