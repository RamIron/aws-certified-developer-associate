# 21.44 - Lambda Function URL

> **Lecture 307** | Section 21: AWS Serverless: Lambda
> Exposing Lambda as an HTTPS endpoint without API Gateway or ALB

---

## What Is a Lambda Function URL?

- A dedicated **HTTPS endpoint** for your Lambda function — no API Gateway or ALB needed
- Unique URL that **never changes**: `https://<url-id>.lambda-url.<region>.on.aws`
- Supports **IPv4 and IPv6**
- Accessible from **public internet only** (no private URL support)
- Can be accessed from: web browser, CLI, Postman, any HTTP client
- Applies to a **function alias** or **$LATEST** — NOT to specific published versions
- Throttling: use **Reserved Concurrency** to control max invocations

```
  ┌──────────┐     HTTPS      ┌──────────────────────────────┐
  │  Browser  │───────────────►│  Lambda Function URL          │
  │  CLI      │                │  https://abc123.lambda-url    │
  │  Postman  │                │  .us-east-1.on.aws            │
  └──────────┘                └──────────────────────────────┘
                                        │
  No API Gateway needed!                ▼
  No ALB needed!                   ┌──────────┐
                                   │  Lambda   │
                                   └──────────┘
```

## Security: AuthType

### AuthType: NONE (Public Access)

- Allows **public and unauthenticated** access
- Must grant public access via **resource-based policy**

```json
{
  "Effect": "Allow",
  "Principal": "*",
  "Action": "lambda:InvokeFunctionUrl",
  "Resource": "arn:aws:lambda:...:function:myFunc"
}
```

```
  Internet ──► Lambda Function URL ──► Lambda
               (AuthType: NONE)
               Resource policy: Allow Principal *
```

### AuthType: AWS_IAM (Authenticated Access)

- IAM is used to **authenticate and authorize** requests
- Requires `lambda:InvokeFunctionUrl` permission
- **Same account:** identity-based policy **OR** resource-based policy = allow
- **Cross account:** identity-based policy **AND** resource-based policy = both must allow

```
  Same Account:
  ┌──────────────────────────────────────────┐
  │  Identity policy OR Resource policy = ✅  │
  │  (either one is enough)                   │
  └──────────────────────────────────────────┘

  Cross Account:
  ┌───── Account A ─────┐   ┌───── Account B ─────┐
  │                      │   │                      │
  │  Lambda Function URL │   │  IAM Role            │
  │  Resource policy:    │   │  Identity policy:    │
  │  Allow Account B ✅  │   │  Allow invoke ✅     │
  │                      │   │                      │
  └──────────────────────┘   └──────────────────────┘
          BOTH must allow for cross-account access
```

## CORS

- Needed when calling the Lambda Function URL from a **different domain**
- Same concept as S3 CORS

```
  example.com (S3 + CloudFront)
       │
       │  Calls API at:
       ▼
  api.example.com (Lambda Function URL)
       │
       └── Different domain = CORS required!
           Configure CORS on the Lambda Function URL
```

## Exam Tips

- Function URL = **HTTPS endpoint without API Gateway or ALB**
- **Public internet only** — no private URL support
- Applies to **aliases** or **$LATEST**, NOT specific versions
- Throttle with **Reserved Concurrency**
- **AuthType NONE** = public, needs resource policy with `Principal: *`
- **AuthType AWS_IAM** = authenticated
  - Same account: identity OR resource policy
  - Cross account: identity AND resource policy (both required)
- CORS needed when calling from a different domain
- Similar to S3 bucket policy logic for same-account vs cross-account
