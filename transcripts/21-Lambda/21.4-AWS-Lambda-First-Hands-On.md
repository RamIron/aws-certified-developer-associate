# 21.4 - AWS Lambda - First Hands On

> Udemy Lecture #267 · Section 21: AWS Serverless: Lambda

## Hands-On Summary

### Creating a Lambda Function
1. Go to Lambda console → Create Function
2. Use **blueprint** → "hello-world" → Python
3. Name: `HelloWorld`
4. **Execution Role**: Create new role with basic Lambda permissions

### Key Observations

**Code:**
- Lambda has an inline code editor in the console
- The **handler** function is what gets invoked when an event arrives
- Input is a JSON event → function processes it → returns a result

**Testing:**
- Click **Test** → create a test event (JSON input)
- Successful execution returns the result + logs
- Bad input → function throws an exception (visible in logs)

**Monitoring:**
- **Monitor** tab → invocation stats from CloudWatch
- **View CloudWatch Logs** → see log streams with execution details + errors
- Debug directly from CloudWatch Logs

**Configuration:**
- **General**: memory (small ↔ large), ephemeral storage, timeout, execution role
- **Permissions**: IAM role with `CloudWatch Logs` actions (create log group, create log stream, put log events)
- To interact with other services (S3, DynamoDB, etc.) → add permissions to the IAM role
- **Triggers**: add event sources (S3, API Gateway, EventBridge, etc.) — shows all possible sources

### Scaling Demo
- The interactive demo at `/begin` shows Lambda scaling automatically
- More event sources triggering → more Lambda instances spin up (1 → 8+)
- No server management needed — scaling is automatic

---

## Exam Tips

- Lambda execution role = IAM role (like EC2 instance profile, but for Lambda)
- Basic Lambda role allows **CloudWatch Logs** writing (3 actions: CreateLogGroup, CreateLogStream, PutLogEvents)
- Need Lambda to access S3/DynamoDB/etc → **add permissions to the IAM role**
- Lambda scales automatically by creating more concurrent instances
