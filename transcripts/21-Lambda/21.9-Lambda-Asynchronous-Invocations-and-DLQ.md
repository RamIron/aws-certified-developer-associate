# 21.9 - Lambda Asynchronous Invocations & DLQ

> Udemy Lecture #272 · Section 21: AWS Serverless: Lambda

## Key Concepts

### 1. How Asynchronous Invocation Works

The caller does NOT wait for a response. Events are placed in an **internal Event Queue** and Lambda processes them.

```
S3 (new file) ──→ ┌──────────────┐ ──→ Lambda function
                   │ Event Queue  │
SNS topic ──────→ │  (internal)  │ ──→ Lambda function
                   └──────────────┘
```

The caller fires and forgets — Lambda handles processing behind the scenes.

### 2. Automatic Retries

If Lambda fails, it **retries automatically** — 3 total attempts:

```
Attempt 1: immediately
Attempt 2: 1 minute after failure
Attempt 3: 2 minutes after attempt 2
```

Because of retries, your Lambda function may process the **same event multiple times** → function MUST be **idempotent** (same result regardless of how many times it runs).

Retries also mean **duplicate log entries** in CloudWatch Logs.

### 3. Dead-Letter Queue (DLQ)

After all 3 retries fail, the event can be sent to a **DLQ** for later investigation:

```
Event → Lambda → fail → retry 1 → fail → retry 2 → fail
                                                      ↓
                                               ┌─────────────┐
                                               │  DLQ (SQS)  │
                                               │   or SNS    │
                                               └─────────────┘
```

DLQ options: **SQS queue** or **SNS topic**.

### 4. Why Use Asynchronous?

- Some services **require** it (S3, SNS, EventBridge)
- **Speed**: process 1000 files in parallel without waiting for each one individually
- You don't need the result immediately — just fire and let Lambda handle it

### 5. Services That Invoke Lambda Asynchronously

| Service | Use Case |
|---------|----------|
| **S3** | Event notifications (new file, delete, etc.) |
| **SNS** | React to topic notifications |
| **CloudWatch Events / EventBridge** | React to AWS infrastructure events |
| CodeCommit | New branch, tag, push |
| CodePipeline | Invoke during pipeline (must callback) |
| CloudWatch Logs | Log processing |
| SES | Email handling |
| CloudFormation | Custom resources |
| Config | Rule evaluations |
| IoT / IoT Events | Device events |

---

## Exam Tips

- Async = caller does NOT wait → event goes to **internal queue** → Lambda processes
- **3 retries** total (immediate, +1 min, +2 min) → function must be **idempotent**
- Failed after all retries → **DLQ** (SQS or SNS)
- S3, SNS, EventBridge → always **asynchronous**
- ALB, API Gateway, CLI/SDK → always **synchronous**
- Idempotent = same result no matter how many times you run it
