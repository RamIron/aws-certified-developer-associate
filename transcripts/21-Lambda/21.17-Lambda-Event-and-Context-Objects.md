# 21.17 - Lambda Event & Context Objects

> Udemy Lecture #280 · Section 21: AWS Serverless: Lambda

## Key Concepts

### 1. Two Objects Passed to Every Lambda Function

Every Lambda handler receives two parameters:

```python
def handler(event, context):
    # event  → WHAT happened (data to process)
    # context → WHERE it's running (metadata about the invocation)
```

### 2. Event Object — "What happened"

JSON document from the **invoking service** containing the data to process.

```python
# Example: EventBridge event
event = {
    "source": "aws.events",
    "detail-type": "Scheduled Event",
    "region": "eu-west-1",
    "detail": { ... }
}

# Example: S3 event
event = {
    "Records": [{
        "s3": {
            "bucket": { "name": "my-bucket" },
            "object": { "key": "photo.jpg" }
        }
    }]
}
```

- Different structure depending on the source (S3, SQS, EventBridge, ALB, etc.)
- Converted to native object based on runtime (Python → dict, Node.js → object)
- Contains everything your function needs to do its job

**More event examples by source:**

```python
# SQS event
event = {
    "Records": [{
        "body": "hello world",
        "messageAttributes": { "foo": { "stringValue": "bar" } },
        "eventSource": "aws:sqs",
        "messageId": "abc-123"
    }]
}

# ALB event
event = {
    "httpMethod": "GET",
    "path": "/lambda",
    "queryStringParameters": { "name": "foo" },
    "headers": { "host": "example.com" },
    "body": None,
    "isBase64Encoded": False
}

# DynamoDB Streams event
event = {
    "Records": [{
        "eventName": "INSERT",
        "dynamodb": {
            "Keys": { "id": { "S": "123" } },
            "NewImage": { "id": { "S": "123" }, "name": { "S": "Brandon" } }
        },
        "eventSource": "aws:dynamodb"
    }]
}
```

### 3. Context Object — "Where it's running"

Metadata about the **invocation and runtime environment**. Same structure regardless of the source.

```python
context.aws_request_id          # Unique ID for this invocation
context.function_name           # "lambda-demo"
context.function_arn            # Full ARN of the function
context.memory_limit_in_mb      # 128, 256, etc.
context.log_group_name          # CloudWatch Log Group
context.log_stream_name         # CloudWatch Log Stream
context.function_version        # "$LATEST" or published version number
context.invoked_function_arn    # ARN including alias/version
context.get_remaining_time_in_millis()  # Time left before timeout
```

> `get_remaining_time_in_millis()` is useful to check if you have enough time left before Lambda kills your function.

### Quick Comparison

```
┌──────────────────────────────────────────────────────┐
│  EVENT                    │  CONTEXT                  │
│                           │                           │
│  What: data to process    │  What: invocation metadata│
│  From: invoking service   │  From: Lambda runtime     │
│  Changes: per source      │  Changes: per invocation  │
│                           │                           │
│  "bucket name?"  → event  │  "request ID?"  → context │
│  "object key?"   → event  │  "function name?" → context│
│  "message body?" → event  │  "memory limit?" → context │
│  "region of event?" → event│ "log group?" → context   │
└──────────────────────────────────────────────────────┘
```

---

## Exam Tips

- "What data triggered the function?" → **event** object
- "What is the request ID / function name / memory limit?" → **context** object
- Event structure varies by source (S3, SQS, EventBridge all look different)
- Context structure is always the same regardless of source
- In Python: event = dict, context = object with attributes
