# 21.35 - Lambda Concurrency Hands On

> **Lecture 298** | Section 21: AWS Serverless: Lambda
> Configuring reserved and provisioned concurrency in the console

---

## What Was Demonstrated

### Reserved Concurrency
- Configuration → Concurrency tab
- Default: **unreserved account concurrency = 1,000** (shared across all functions)
- Set reserved concurrency to **20** → account drops to **980 unreserved** for other functions
- Set reserved concurrency to **0** → function is **always throttled** (good for testing throttle handling)
- Invocation with 0 concurrency → error: *"Calling the invoke API action failed — exceeded the rate"*

### Provisioned Concurrency
- Requires a **published version or alias** (cannot use `$LATEST`)
- Specify number of pre-warmed instances (e.g., 5)
- Has **associated cost** — not free!
- Setting shown in demo but not saved (versions/aliases covered in future lectures)

---

## Exam Relevance

- Reserved concurrency of **0** = function is always throttled (useful for testing or disabling)
- Provisioned concurrency only works on **published versions or aliases**, NOT `$LATEST`
- Provisioned concurrency has **additional cost**
