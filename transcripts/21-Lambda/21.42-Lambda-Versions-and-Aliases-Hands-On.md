# 21.42 - Lambda Versions and Aliases - Hands On

> **Lecture 305** | Section 21: AWS Serverless: Lambda
> Creating versions, aliases, and weighted canary deployments in the console

---

## What Was Demonstrated

### 1. Creating Versions
- Created `lambda-version-demo` (Python 3.8)
- Code returns `"this is version one"` → deployed → tested ✅
- Actions → **Publish New Version** → V1 created (immutable)
- On V1: code editor says *"Designer is only available on the unpublished function"* — **can't edit**
- Went back to `$LATEST`, changed code to `"this is version two"` → deployed → published → V2

### 2. Creating Aliases
- **DEV** alias → points to `$LATEST` (always the most recent code)
- **TEST** alias → points to **V2** (latest published version)
- **PROD** alias → points to **V1** (stable, known good)

### 3. Weighted Alias (Canary Deployment)
- Edited PROD alias → added **weighted alias**:
  - 50% → V1
  - 50% → V2 (aggressive for demo; normally 90/10 or 95/5)
- Testing alternated between `"this is version one"` and `"this is version two"`
- When happy with V2 → edited PROD alias, removed weight, pointed 100% to V2

---

## Key Observations

- Published versions **cannot be edited** in the console (code editor is locked)
- Versions tab shows all published versions
- Aliases tab lets you create, edit, and weight aliases
- Weighted aliases show canary behavior immediately in test results
- Final step: remove weighted alias → point 100% to new version = **full deployment**

---

## Exam Relevance

- DEV → `$LATEST`, TEST → latest published, PROD → stable version = common pattern
- Weighted aliases = canary deployment in action
- Can't edit code on a published version (immutable confirmed in console)
