# 21.48 - Lambda Best Practices

> **Lecture 311** | Section 21: AWS Serverless: Lambda
> Final words of wisdom before leaving the Lambda section

---

## Best Practices Summary

1. **Heavy work OUTSIDE the handler**
   - DB connections, AWS SDK init, datasets → outside the handler
   - Minimizes handler execution time (reuses execution context)

2. **Use environment variables**
   - DB connection strings, S3 bucket names, config values
   - Don't hardcode values in your code
   - Encrypt sensitive values (passwords, secrets) with **KMS**

3. **Minimize deployment package size**
   - Only include what you need at runtime
   - If too big → break it down
   - Reuse libraries → use **Lambda Layers**
   - Remember the limits: 50 MB compressed / 250 MB uncompressed

4. **NEVER have Lambda call itself (no recursion!)**
   - A Lambda function invoking itself = infinite loop
   - Extremely expensive and dangerous
   - This is a disaster scenario — avoid at all costs

---

## Exam Tips

- Init outside handler = #1 best practice (exam loves pseudocode questions on this)
- Environment variables for config, KMS for secrets
- Minimize package size, use Layers for shared libs
- **Lambda recursion = NEVER** (exam will test this)
