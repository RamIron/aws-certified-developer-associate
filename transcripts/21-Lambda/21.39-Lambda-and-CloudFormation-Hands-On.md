# 21.39 - Lambda and CloudFormation - Hands On

> **Lecture 302** | Section 21: AWS Serverless: Lambda
> Creating a Lambda function via CloudFormation with S3-based code deployment

---

## What Was Demonstrated

### 1. CloudFormation Template Structure (`lambda-xray.yaml`)

**Parameters:**
- `S3Bucket` — bucket containing the zip
- `S3Key` — file name (e.g., `function.zip`)
- `S3ObjectVersion` — version ID (since versioning is enabled)

**Resources:**
- **IAM Role** with policy allowing: CloudWatch Logs, X-Ray traces, S3 Get/List
- **Lambda Function** referencing the S3 parameters, runtime `nodejs14.x`, timeout 10s, X-Ray tracing enabled (`TracingConfig: Mode: Active`)

### 2. Setup Steps
1. Created S3 bucket with **versioning enabled**
2. Uploaded `function.zip` to the bucket
3. Opened CloudFormation → Create Stack → Upload template
4. Filled parameters: bucket name, key (`function.zip`), object version ID
5. Acknowledged IAM role creation → Create Stack

### 3. Result
- Stack created successfully → Lambda function appeared in console
- Console showed: *"This function belongs to an application"* (CloudFormation integration detected)
- Function tested successfully (returned S3 bucket list)
- X-Ray traces appeared (Active Tracing enabled via template)
- Cleanup: delete the CloudFormation stack → removes Lambda + IAM role

---

## Key Takeaways

- CloudFormation can define **everything**: IAM role, Lambda function, X-Ray config
- S3 **versioning is important** — you need the `S3ObjectVersion` parameter
- Lambda console detects CloudFormation-managed functions automatically
- Delete the stack = clean up all resources (Lambda + role)
