# 21.16 - Lambda Event Source Mapping Hands On (SQS)

> Udemy Lecture #279 · Section 21: AWS Serverless: Lambda

## Hands-On Summary

### SQS Event Source Mapping

**Setup:**
1. Create Lambda function → `lambda-sqs`, Python
2. Create SQS queue → `lambda-demo-sqs` (Standard)
3. Lambda → **Add Trigger** → SQS → select queue
   - Batch size: 1–10 (or larger)
   - Batch window: seconds to wait before invoking (for efficiency)
   - Enable trigger: yes

**Permission error!** Lambda needs `sqs:ReceiveMessage` to poll SQS.

**Fix:** Lambda execution role → attach **AWSLambdaSQSQueueExecutionRole** policy

This policy gives Lambda permission to:
- `sqs:ReceiveMessage`
- `sqs:DeleteMessage`
- `sqs:GetQueueAttributes`

### Testing
1. SQS → Send message → body: "hello world", attribute: foo=bar
2. Lambda polls automatically → processes message
3. CloudWatch Logs shows the event with body, message attributes, event source
4. Back in SQS → **0 messages available** (Lambda deleted it after processing)

### SQS Event Payload

```json
{
  "Records": [{
    "body": "hello world",
    "messageAttributes": {
      "foo": { "stringValue": "bar" }
    },
    "eventSource": "aws:sqs",
    ...
  }]
}
```

### Kinesis Trigger Options (shown but not created)

| Option | Purpose |
|--------|---------|
| **Batch size** | How many records per batch (default 100) |
| **Batch window** | Wait time to build bigger batch |
| **Starting position** | Latest, Earliest (TRIM_HORIZON), or Timestamp |
| **On-failure destination** | Where to send discarded data |
| **Retry attempts** | How many times to retry failed batch |
| **Max age of record** | Discard records older than this |
| **Split batch on error** | Try smaller batches on timeout |
| **Concurrent batches per shard** | Parallelization factor (1–10) |
| **Tumbling window** | For aggregations |
| **Report batch item failures** | Report individual item failures |

### Clean Up
- **Disable the SQS trigger** — otherwise Lambda keeps polling (costs money / free tier usage)

## Exam Tips

- Lambda needs **IAM execution role** with SQS permissions to poll (AWSLambdaSQSQueueExecutionRole)
- This is different from async where the **source** needs permission to invoke Lambda (resource-based policy)
- Event Source Mapping: **Lambda pulls** → needs IAM role permissions
- Async/Sync: **Source pushes** → needs resource-based policy on Lambda
- After processing, Lambda **deletes** messages from SQS (0 messages remaining)
- Kinesis trigger has many more options than SQS (parallelization, split batch, etc.)
