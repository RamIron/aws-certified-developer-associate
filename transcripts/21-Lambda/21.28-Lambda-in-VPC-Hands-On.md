# 21.28 - Lambda in VPC - Hands On

> **Lecture 291** | Section 21: AWS Serverless: Lambda
> Deploying a Lambda function inside a VPC and observing ENI creation

---

## What Was Done

1. **Created Lambda function** (`Lambda-VPC`, Python 3.8)
2. **Created Security Group** (`Lambda SG`) in EC2 console — no inbound rules needed, outbound rules define access to other services
3. **Configured VPC on Lambda:**
   - Configuration → VPC → Edit
   - Selected VPC, picked subnets, attached Lambda SG
   - AWS Console shows warning: *"When you connect a function to a VPC, it does not have access to the internet unless you provide your VPC access"*

---

## Key Observations

### Permission Error
- First attempt to save VPC config **failed** — Lambda couldn't call `CreateNetworkInterface` on EC2
- **Fix:** Attached **AWSLambdaENIManagementAccess** policy to the Lambda execution role
  - Grants: `CreateNetworkInterface`, `DeleteNetworkInterface`, `DescribeNetworkInterfaces`, etc.

> **Note:** This is similar to the `AWSLambdaVPCAccessExecutionRole` mentioned in theory — both provide ENI management permissions

### ENI Creation
- After saving, Lambda took **~3 minutes** to update (AWS setting up ENIs)
- In EC2 → Network Interfaces: **3 ENIs created** (one per subnet/AZ)
- These ENIs are what allow Lambda to communicate within the VPC

### Public Subnet ≠ Internet
- Even though the subnets selected were public subnets, the **Lambda function still does NOT have internet access**
- Confirmed the theory: Lambda in public subnet ≠ internet access (unlike EC2)

---

## Exam Relevance

- If Lambda VPC config fails → check that the execution role has **ENI management permissions**
- Lambda in VPC creates **ENIs** in your subnets — visible in EC2 console
- Initial VPC deployment takes a few minutes (ENI setup), subsequent invocations are fast
