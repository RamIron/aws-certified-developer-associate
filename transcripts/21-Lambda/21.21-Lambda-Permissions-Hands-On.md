# 21.21 - Lambda Permissions - IAM Roles & Resource Policies - Hands On

> Udemy Lecture #284 · Section 21: AWS Serverless: Lambda

## Hands-On Summary

### Every Lambda Has an IAM Role

IAM console → Roles → filter by "Lambda" → shows all Lambda roles created so far.

### BasicExecutionRole (on every Lambda)

```json
{
  "Effect": "Allow",
  "Action": [
    "logs:CreateLogGroup",
    "logs:CreateLogStream",
    "logs:PutLogEvents"
  ],
  "Resource": "*"
}
```

Allows Lambda to write logs to CloudWatch. Attached to every Lambda role created via console.

### Resource-Based Policies — Verified in Console

**Lambda-S3** (S3 → Lambda):
- Configuration → Permissions → Resource-based policy ✅
- Allows `s3.amazonaws.com` to `lambda:InvokeFunction`
- Condition: specific S3 bucket ARN + source account

**Lambda-EventBridge** (EventBridge → Lambda):
- Configuration → Permissions → Resource-based policy ✅
- Allows `events.amazonaws.com` to `lambda:InvokeFunction`
- Condition: specific EventBridge rule ARN

**Lambda-SQS** (Lambda polls SQS):
- Configuration → Permissions → **NO resource-based policy** ❌
- Instead: execution role has `AWSLambdaSQSQueueExecutionRole`
- Permissions: `sqs:ReceiveMessage`, `sqs:DeleteMessage`, `sqs:GetQueueAttributes`

### The Pattern Confirmed

```
┌───────────────────────────────────────────────────────┐
│  SERVICE PUSHES TO LAMBDA (S3, EventBridge, ALB)      │
│                                                       │
│  → Resource-based policy ON Lambda                    │
│  → "I allow service X to invoke me"                   │
│  → Lambda execution role: only BasicExecutionRole     │
├───────────────────────────────────────────────────────┤
│  LAMBDA PULLS FROM SERVICE (SQS, Kinesis, DDB)       │
│                                                       │
│  → NO resource-based policy needed                    │
│  → Execution role has read permissions for the source │
│  → "I have permission to read from service X"         │
└───────────────────────────────────────────────────────┘
```

---

## Exam Tips

- S3/EventBridge/ALB invoke Lambda → check **resource-based policy** (under Permissions tab)
- SQS/Kinesis/DDB polled by Lambda → check **execution role** (IAM role with read permissions)
- No resource-based policy on Lambda-SQS → because SQS doesn't invoke Lambda, Lambda reads from SQS
- BasicExecutionRole = CloudWatch Logs only (CreateLogGroup, CreateLogStream, PutLogEvents)
