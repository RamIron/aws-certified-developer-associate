# 21.3 - AWS Lambda Overview

> Udemy Lecture #266 · Section 21: AWS Serverless: Lambda

## Key Concepts

### 1. EC2 vs Lambda

| | EC2 | Lambda |
|---|---|---|
| **Servers** | You provision and manage | No servers to manage |
| **Running** | Continuously (even idle) | On demand — only runs when invoked |
| **Scaling** | ASG (you configure) | Automatic — AWS handles concurrency |
| **Time limit** | Unlimited | Max **15 minutes** per execution |
| **Billing** | Per hour/second (always on) | Per invocation + compute duration |

### 2. Lambda Benefits & Pricing

**Benefits:**
- Pay per request + compute time
- Free tier: **1 million requests** + **400,000 GB-seconds**/month
- Integrated with tons of AWS services
- Easy monitoring via CloudWatch
- Up to **10 GB RAM** per function
- **More RAM = better CPU + network** (important for exam!)

**Pricing:**
- Per calls: first 1M free, then **$0.20 per 1M requests**
- Per duration: billed in **1ms increments**
- 400,000 GB-seconds free = 400,000s at 1 GB RAM = 3,200,000s at 128 MB RAM

### 3. Supported Languages

| Language | Notes |
|----------|-------|
| **Node.js** | Most popular for exam |
| **Python** | Most popular for exam |
| Java | JVM-based |
| C# | .NET Core / PowerShell |
| Ruby | |
| Rust, Go, etc. | Via **Custom Runtime API** |
| **Container Images** | Must implement **Lambda Runtime API** |

> **Exam trap:** For running Docker containers → prefer **ECS/Fargate** over Lambda. Lambda supports containers but it's not the go-to for generic Docker workloads.

### 4. Key Integrations

| Service | Integration |
|---------|-------------|
| **API Gateway** | REST API → invokes Lambda |
| **Kinesis** | Real-time data transformation |
| **DynamoDB** | Triggers (react to DB changes) |
| **S3** | Event notifications (file created/deleted) |
| **CloudFront** | Lambda@Edge |
| **EventBridge** | React to AWS infrastructure events |
| **CloudWatch Logs** | Stream logs anywhere |
| **SNS** | React to topic notifications |
| **SQS** | Process queue messages |
| **Cognito** | React to user login events |

### 5. Example Use Cases

**Serverless Thumbnail Creation:**
```
New image → S3 bucket
              ↓ (S3 event notification)
           Lambda (generate thumbnail)
            ↓              ↓
    S3 (thumbnail)    DynamoDB (metadata: name, size, date)
```

**Serverless CRON Job:**
```
EventBridge Rule (every 1 hour)
       ↓
    Lambda (perform scheduled task)
```
- No idle EC2 wasted — both EventBridge and Lambda are serverless

## Exam Tips

- Lambda max execution time = **15 minutes**
- Max RAM = **10 GB** (more RAM → better CPU + network)
- Free tier: **1M requests + 400,000 GB-seconds**
- Billing in **1ms increments**
- Docker containers on exam → **ECS/Fargate** (not Lambda, unless it implements Lambda Runtime API)
- Serverless CRON → **EventBridge + Lambda** (not EC2)
- S3 event → Lambda is a classic exam pattern
