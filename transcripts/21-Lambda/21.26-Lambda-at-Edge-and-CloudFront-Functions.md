# 21.26 - Lambda@Edge & CloudFront Functions

> **Lecture 289** | Section 21: AWS Serverless: Lambda
> Customizing CDN behavior by running code at CloudFront edge locations

---

## Why Edge Functions?

- Applications are deployed in a **specific region**, but CloudFront distributes content via **edge locations** worldwide
- Sometimes you need to execute logic **at the edge** before reaching the origin
- **Edge Functions** = code you attach to CloudFront distributions, running **close to users** to minimize latency
- Fully **serverless**, deployed globally, pay per use

---

## Two Types of Edge Functions

```
CloudFront has TWO edge function types:

┌─────────────────────────┐    ┌─────────────────────────┐
│   CloudFront Functions  │    │      Lambda@Edge         │
│                         │    │                          │
│  - JavaScript only      │    │  - Node.js or Python     │
│  - < 1 ms execution     │    │  - Up to 5-10 seconds    │
│  - Millions req/sec     │    │  - Thousands req/sec     │
│  - Viewer only          │    │  - All 4 stages          │
│  - Managed in CF        │    │  - Authored in us-east-1 │
└─────────────────────────┘    └─────────────────────────┘
```

## The 4 Stages of a CloudFront Request

```
          ┌──────────┐
          │  Client   │
          └────┬──┬───┘
               │  ▲
    Viewer     │  │  Viewer
    Request ①  │  │  Response ④
               ▼  │
          ┌──────────┐
          │CloudFront│
          └────┬──┬───┘
               │  ▲
    Origin     │  │  Origin
    Request ②  │  │  Response ③
               ▼  │
          ┌──────────┐
          │  Origin   │
          └──────────┘

  CloudFront Functions  →  ① ④ only (top half)
  Lambda@Edge           →  ① ② ③ ④  (entire flow)
```

### Where Each Function Type Can Act

| Stage | CloudFront Functions | Lambda@Edge |
|-------|---------------------|-------------|
| ① Viewer Request | Yes | Yes |
| ② Origin Request | **No** | Yes |
| ③ Origin Response | **No** | Yes |
| ④ Viewer Response | Yes | Yes |

---

## CloudFront Functions — Details

- **Language:** JavaScript only
- **Scale:** Millions of requests per second
- **Execution time:** Sub-millisecond (< 1 ms)
- **Scope:** Viewer request & viewer response ONLY
- **Management:** Native feature, code managed entirely within CloudFront
- **Startup:** Sub-millisecond startup times

### CloudFront Functions Use Cases
- **Cache key normalization** — transform request attributes for optimal cache keys
- **Header manipulation** — insert, modify, or delete HTTP headers
- **URL rewrites or redirects**
- **Request authorization** — create and validate JWT tokens to allow/deny requests

> All of these can be done in < 1 ms

---

## Lambda@Edge — Details

- **Language:** Node.js or Python
- **Scale:** Thousands of requests per second
- **Execution time:** Up to 5-10 seconds
- **Scope:** All 4 stages (viewer + origin, request + response)
- **Authoring region:** us-east-1 (same as CloudFront distribution management)
- **Deployment:** CloudFront replicates function to ALL edge locations

### Lambda@Edge Use Cases
- Longer execution time (up to 10 seconds)
- Adjustable CPU and memory
- Can load **third-party libraries** (including AWS SDK to access other services)
- **Network access** to external services for processing
- **File system access**
- **Access to the HTTP request body**

> Use Lambda@Edge when you need more power, integrations, or origin-level logic

---

## Comparison Table

| Feature | CloudFront Functions | Lambda@Edge |
|---------|---------------------|-------------|
| **Runtime** | JavaScript | Node.js, Python |
| **Scale** | Millions req/sec | Thousands req/sec |
| **Trigger points** | Viewer only (① ④) | All 4 stages (① ② ③ ④) |
| **Max execution time** | < 1 ms | 5-10 seconds |
| **Max memory** | 2 MB | 128 MB up to 10 GB |
| **Total package size** | 10 KB | 1 MB – 50 MB |
| **Network / File system access** | No | Yes |
| **Access to request body** | No | Yes |
| **3rd-party libraries** | No | Yes |
| **Pricing** | Free tier available, 1/6th price of @Edge | No free tier, per request & duration |
| **Authoring region** | Managed within CloudFront | us-east-1 (replicated globally) |

## General Edge Functions Use Cases

- Website security and privacy
- Dynamic web applications at the edge
- SEO (Search Engine Optimization)
- Intelligent routing across origins and data centers
- Bot mitigation at the edge
- Real-time image transformation
- A/B testing
- User authentication and authorization
- User prioritization
- User tracking and analytics

---

## Exam Tips

- **CloudFront Functions** = lightweight, JavaScript, sub-millisecond, viewer only, millions req/sec → think **simple and fast** (JWT validation, header manipulation, URL rewrites)
- **Lambda@Edge** = Node.js/Python, up to 10 seconds, all 4 stages, external access → think **complex logic** (SDK calls, body processing, origin manipulation)
- If a question asks about modifying the **origin request/response** → only **Lambda@Edge** can do that
- If a question asks about **millions of requests** with simple logic → **CloudFront Functions**
- Lambda@Edge functions are authored in **us-east-1** and replicated globally
- Both are **serverless** and **fully managed**
