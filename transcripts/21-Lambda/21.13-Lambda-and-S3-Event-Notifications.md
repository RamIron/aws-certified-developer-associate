# 21.13 - Lambda & S3 Event Notifications

> Udemy Lecture #276 · Section 21: AWS Serverless: Lambda

## Key Concepts

### 1. S3 Event Notifications Recap

Triggers: object **created, removed, restored**, or **replicated**. Can filter by prefix and suffix.

### 2. Three Destination Patterns

```
                    ┌──→ SNS ──→ fan out to multiple SQS
                    │
S3 event ───────────┼──→ SQS ──→ Lambda reads from queue
                    │
                    └──→ Lambda (async invocation)
                              │
                              └──→ DLQ (SQS) on failure
```

The direct S3 → Lambda path is an **asynchronous invocation** (with retries and optional DLQ).

### 3. Versioning Matters

- S3 events typically deliver in **seconds** (sometimes 1+ minute)
- If two writes to the **same object** happen at the exact same time → you may only get **one notification**
- Fix: **enable versioning** on your bucket to guarantee you receive all notifications

### 4. Common Use Case

```
S3 bucket (new file)
       ↓ (async)
    Lambda (process file)
       ↓
  DynamoDB or RDS (store data)
```

Classic pattern: upload file → Lambda processes it → store results in a database.

---

## Exam Tips

- S3 → Lambda = **asynchronous** invocation (retries apply, DLQ available)
- Enable **versioning** to avoid missing notifications on concurrent writes to same object
- S3 notifications can go to: **SNS, SQS, or Lambda**
- S3 → SNS → multiple SQS = **fan out pattern**
- Thumbnail generation from S3 uploads = classic Lambda exam scenario
