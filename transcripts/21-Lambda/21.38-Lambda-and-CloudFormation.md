# 21.38 - Lambda and CloudFormation

> **Lecture 301** | Section 21: AWS Serverless: Lambda
> Two ways to deploy Lambda via CloudFormation: inline code vs S3 zip

---

## Two Ways to Deploy Lambda via CloudFormation

### Option 1: Inline Code

- Use the `Code.ZipFile` property in the CloudFormation template
- Lambda code is written **directly inside** the template
- **Cannot include dependencies** — simple functions only

```yaml
AWSTemplateFormatVersion: '2010-09-09'
Description: Lambda function inline
Resources:
  primer:
    Type: AWS::Lambda::Function
    Properties:
      Runtime: python3.x
      Role: arn:aws:iam::123456789012:role/lambda-role
      Handler: index.handler
      Code:
        ZipFile: |
          import os

          DB_URL = os.getenv("DB_URL")
          db_client = db.connect(DB_URL)
          def handler(event, context):
              user = db_client.get(user_id = event["user_id"])
              return user
```

### Option 2: S3 Zip (Recommended)

- Store the Lambda zip in **Amazon S3**
- Reference it in CloudFormation with three properties:

| Property | Description |
|----------|-------------|
| `S3Bucket` | The S3 bucket name |
| `S3Key` | Full path to the zip file |
| `S3ObjectVersion` | Version ID (if versioned bucket) |

```yaml
AWSTemplateFormatVersion: '2010-09-09'
Description: Lambda from S3
Resources:
  Function:
    Type: AWS::Lambda::Function
    Properties:
      Handler: index.handler
      Role: arn:aws:iam::123456789012:role/lambda-role
      Code:
        S3Bucket: my-bucket
        S3Key: function.zip
        S3ObjectVersion: String
      Runtime: nodejs12.x
```

---

## Important: S3 Versioning & CloudFormation Updates

If you update the code in S3 but **don't change** `S3Bucket`, `S3Key`, or `S3ObjectVersion` in the template → **CloudFormation will NOT update** the function!

```
  Upload new code to S3
         │
         ├── S3ObjectVersion unchanged in template → ❌ No update!
         │
         └── S3ObjectVersion updated in template   → ✅ CloudFormation updates Lambda
```

> **Best practice:** Enable **S3 versioning** and update `S3ObjectVersion` in the template when you deploy new code

## Cross-Account Deployment

Deploy Lambda code from Account 1's S3 bucket to functions in Account 2 and Account 3:

```
  ┌── Account 1 ──────────────┐
  │                            │
  │  ┌────────────────────┐   │
  │  │  S3 Bucket          │   │
  │  │  (Lambda code .zip) │   │
  │  │                      │   │
  │  │  Bucket Policy:      │   │
  │  │  Allow Account 2 ✅  │   │
  │  │  Allow Account 3 ✅  │   │
  │  └──────┬──────┬───────┘   │
  └─────────┼──────┼───────────┘
            │      │
            ▼      ▼
  ┌─ Account 2 ─┐  ┌─ Account 3 ─┐
  │              │  │              │
  │ CloudForm.   │  │ CloudForm.   │
  │ Exec Role:   │  │ Exec Role:   │
  │ s3:Get ✅    │  │ s3:Get ✅    │
  │ s3:List ✅   │  │ s3:List ✅   │
  │              │  │              │
  │ → Lambda     │  │ → Lambda     │
  └──────────────┘  └──────────────┘
```

Two things needed per target account:
1. **Bucket Policy** on Account 1's S3 bucket → allow access from other accounts
2. **CloudFormation Execution Role** in each target account → permissions to get/list from S3

---

## Exam Tips

- **Inline** (`Code.ZipFile`) = simple functions only, **no dependencies**
- **S3 zip** = recommended for real functions with dependencies
- Must update `S3Bucket`, `S3Key`, or **`S3ObjectVersion`** for CloudFormation to detect changes
- **Enable S3 versioning** → update `S3ObjectVersion` on each deploy
- Cross-account: needs **S3 bucket policy** + **CloudFormation execution role**
