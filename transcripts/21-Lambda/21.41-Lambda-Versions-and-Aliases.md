# 21.41 - Lambda Versions and Aliases

> **Lecture 304** | Section 21: AWS Serverless: Lambda
> Publishing immutable versions and creating mutable aliases for stable endpoints and canary deployments

---

## Lambda Versions

- While working on Lambda, you use **$LATEST** — this is **mutable** (you can edit code, env vars, etc.)
- When you're happy with your code, you **publish** it → creates an immutable version (V1, V2, V3...)
- **Immutable** = code, environment variables, configuration **cannot be changed** after publishing
- Each version gets its own **ARN** (Amazon Resource Name)
- Version numbers are **increasing** (V1, V2, V3...)
- Both `$LATEST` and published versions can be accessed independently

```
  $LATEST (mutable — edit freely)
     │
     │── Publish ──► V1 (immutable, own ARN)
     │── Publish ──► V2 (immutable, own ARN)
     │── Publish ──► V3 (immutable, own ARN)
```

---

## Lambda Aliases

Aliases are **mutable pointers** to Lambda function versions. They give your users a **stable endpoint** that you can redirect behind the scenes.

```
  ┌─────────────────────────────────────────────┐
  │                                              │
  │  $LATEST ◄──── DEV alias (mutable pointer)  │
  │                                              │
  │  V2 ◄──────── TEST alias (mutable pointer)  │
  │                                              │
  │  V1 ◄──────── PROD alias (mutable pointer)  │
  │                                              │
  └─────────────────────────────────────────────┘

  Users call the ALIAS (stable URL)
  You change where it POINTS (flexible)
```

- Each alias gets its **own ARN**
- Aliases enable stable configuration for triggers and destinations
- **Aliases CANNOT reference other aliases** — only versions! (exam trap)

---

## Canary Deployments with Aliases

Aliases can split traffic between **two versions** using weights:

```
  PROD Alias
     │
     ├── 95% ──► V1 (stable, known good)
     │
     └──  5% ──► V2 (new, testing in prod)

  Later, when confident:

  PROD Alias
     │
     └── 100% ──► V2 (fully deployed)
```

This allows **gradual rollout** — test V2 with a small percentage of real traffic before switching fully.

---

## Exam Tips

- **$LATEST** = mutable (can edit), **published versions** = immutable (frozen)
- Each version has its **own ARN**
- **Aliases** = mutable pointers to versions → stable endpoints for users
- Aliases enable **canary deployments** (weighted traffic split between 2 versions)
- **Aliases CANNOT reference other aliases** — only versions!
- Provisioned Concurrency is set on **published versions or aliases**, NOT $LATEST
