# 21.40 - Lambda Container Images

> **Lecture 303** | Section 21: AWS Serverless: Lambda
> Deploying Lambda functions as container images from ECR, up to 10 GB

---

## Lambda Container Images Overview

- Deploy Lambda functions as **container images up to 10 GB** from **Amazon ECR**
- Pack complex/large dependencies in a Docker container
- The base image **must implement the Lambda Runtime API**
- Not just any Docker image — it must be built on a **Lambda-compatible base image**

```
  ┌─────────────────────────────────┐
  │  Lambda Container Image         │
  │                                  │
  │  ┌──────────────────────────┐   │
  │  │ Your code + dependencies  │   │
  │  │ (app.js, node_modules)    │   │
  │  └──────────────────────────┘   │
  │  ┌──────────────────────────┐   │
  │  │ AWS Base Image            │   │
  │  │ (implements Lambda        │   │
  │  │  Runtime API)             │   │
  │  └──────────────────────────┘   │
  └─────────────────────────────────┘
              │
              ▼
         Amazon ECR ───► Lambda
```

---

## Supported Languages (AWS Base Images)

Python, Node.js, Java, .NET, Go, Ruby

You can also create your **own base image** as long as it implements the **Lambda Runtime API**.

---

## Example Dockerfile

```dockerfile
# 1. Choose base image (implements Lambda Runtime API)
FROM amazon/aws-lambda-nodejs:12

# 2. Copy application code and files
COPY app.js package.json ./

# 3. Install dependencies
RUN npm install

# 4. Set the handler function
CMD ["app.lambdaHandler"]
```

## Unified Workflow

Container images give you a **single workflow** for both ECS and Lambda:

```
  Build container → Push to ECR → Deploy to Lambda OR ECS

  ┌──────────┐     ┌─────────┐     ┌──────────┐
  │  Docker   │────►│   ECR   │────►│  Lambda   │
  │  Build    │     │         │────►│  ECS      │
  └──────────┘     └─────────┘     └──────────┘
```

- Test locally using **Lambda Runtime Interface Emulator**

---

## Best Practices

1. **Use AWS-provided base images** (built on Amazon Linux 2) — they're **cached by Lambda**, faster pulls
2. **Multi-stage builds** — do complex compilation in preliminary stages, copy only final artifacts to the output image → smaller final image
3. **Layer ordering** — stable layers first (base packages), frequently changing layers last (your code) → better caching
4. **Single ECR repository** for functions with large layers → ECR deduplicates shared layers, avoids storing duplicates

---

## Exam Tips

- Lambda container images up to **10 GB** from **ECR**
- Base image **must implement the Lambda Runtime API** — NOT any Docker image!
- Best use case: very **large Lambda functions** with complex dependencies
- AWS provides base images for Python, Node.js, Java, .NET, Go, Ruby
- Can create custom base images (must implement Runtime API)
- Test locally with **Lambda Runtime Interface Emulator**
- Prefer AWS base images → **cached by Lambda service** → faster cold starts
