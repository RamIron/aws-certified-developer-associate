# 31.3 - Amazon OpenSearch Service - Overview

## What is OpenSearch?

Amazon OpenSearch Service is the successor to **Amazon ElasticSearch** (name changed due to licensing issues).

## Key Differentiator vs DynamoDB

| Feature | DynamoDB | OpenSearch |
|---|---|---|
| Query by | Primary key or indexes only | **Any field**, including partial matches |
| Use case | Main data store | Search complement |

> OpenSearch is used **as a complement** to another database, not as a replacement.

## Two Provisioning Modes

| Mode | Description |
|---|---|
| **Managed cluster** | Real EC2 instances are provisioned and visible |
| **Serverless** | AWS handles all scaling and operations |

## Query Language

- OpenSearch has its **own query language**
- Does **NOT** natively support SQL
- SQL compatibility available via a **plugin**

## Data Ingestion Sources

- Kinesis Data Firehose
- IoT
- CloudWatch Logs
- Custom applications

## Security

- Cognito + IAM integration
- Encryption at rest and in-flight

## Analytics

- **OpenSearch Dashboards** — visualizations on top of OpenSearch data

## Common Architecture Patterns

### Pattern 1: DynamoDB + OpenSearch (search on top of DynamoDB)

```
User writes data → DynamoDB Table
                       ↓ DynamoDB Streams
                    Lambda Function
                       ↓ (real time)
                  Amazon OpenSearch
                       ↑
App searches partial term → gets item ID → calls DynamoDB for full item
```

> OpenSearch provides search capability; DynamoDB remains the source of truth.

### Pattern 2: CloudWatch Logs → OpenSearch

**Option A (real time):**
```
CloudWatch Logs → Subscription Filter → Lambda (AWS-managed) → OpenSearch
```

**Option B (near real time):**
```
CloudWatch Logs → Subscription Filter → Kinesis Data Firehose → OpenSearch
```

### Pattern 3: Kinesis → OpenSearch

**Option A (near real time):**
```
Kinesis Data Streams → Kinesis Data Firehose → (optional Lambda transform) → OpenSearch
```

**Option B (real time, custom):**
```
Kinesis Data Streams → Lambda (custom code) → OpenSearch
```

---

## Exam Tips 🎯

- **Search any field / partial match** → OpenSearch (vs DynamoDB which needs indexes)
- **Successor to ElasticSearch** — same thing, new name
- **Two modes**: managed cluster vs serverless
- **No native SQL** — but plugin available
- Firehose = **near real time**; Lambda = **real time**
