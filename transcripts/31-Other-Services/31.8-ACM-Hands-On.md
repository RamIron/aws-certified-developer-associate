# 31.8 - Amazon Certificate Manager (ACM) - Hands On

## What was demonstrated

1. Requested a public TLS certificate for `acmdemo.stephantheteacher.com`
2. Used **DNS validation** (easiest method — direct integration with Route 53)
3. Created the validation DNS record in Route 53 with one click from ACM
4. Certificate issued successfully
5. Created an Elastic Beanstalk environment with a **high availability** config (ALB)
6. Added an **HTTPS listener on port 443** to the ALB, loaded the ACM certificate
7. Created a **CNAME record in Route 53** pointing the custom domain to the Beanstalk URL
8. Verified HTTPS connection in browser (padlock icon, certificate issued by Amazon)
9. Confirmed in EC2 Load Balancer console that the ACM cert is loaded on the 443 listener

## Key takeaways

- DNS validation + Route 53 = one-click certificate validation
- The certificate is loaded on the **load balancer**, not the EC2 instances
- No security group changes needed for HTTPS to work through the ALB
- You can view/change certificates directly from the ALB listener UI
