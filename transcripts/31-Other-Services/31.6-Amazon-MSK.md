# 31.6 - Amazon MSK - Overview

## What is MSK?

**Amazon Managed Streaming for Apache Kafka** — fully managed Kafka cluster on AWS.

- Kafka is an **alternative to Amazon Kinesis** for streaming data
- MSK creates/manages **Kafka broker nodes** and **Zookeeper nodes**
- Deployed in your **VPC, across multiple AZs** (up to 3) for HA
- Automatic recovery from common Kafka failures
- Data stored on **EBS volumes** (for as long as you want — even over 1 year)

## MSK Serverless

- Run Kafka on MSK without provisioning servers
- MSK automatically provisions resources and scales compute + storage

## How Kafka works

```
Producers → Kafka Topic (replicated across brokers) → Consumers
(Kinesis, IoT, RDS)                                   (EMR, S3, SageMaker, Kinesis, RDS)
```

## Kinesis Data Streams vs Amazon MSK

| Feature | Kinesis Data Streams | Amazon MSK |
|---|---|---|
| Message size limit | 1 MB (default) | 1 MB default, **configurable (e.g. 10 MB)** |
| Scaling unit | Shards | Kafka Topics with Partitions |
| Scale up | Shard Splitting | Add partitions |
| Scale down | Shard Merging | **Cannot remove partitions** |
| In-flight encryption | Yes | Plaintext or TLS |
| At-rest encryption | Yes | Yes |
| Data retention | Limited | **As long as you want** (pay for EBS) |

## MSK Consumers

- **Kinesis Data Analytics for Apache Flink**
- **AWS Glue** (streaming ETL, powered by Apache Spark Streaming)
- **Lambda** (MSK as event source)
- **Custom Kafka consumer** on EC2, ECS, or EKS

## Exam Tips 🎯

- MSK = managed Kafka = **alternative to Kinesis**
- MSK can configure message size **above 1 MB** (Kinesis cannot)
- MSK data retention: **unlimited** (Kinesis is limited)
- Cannot remove partitions in MSK — can only add them
