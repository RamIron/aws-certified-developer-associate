# 31.9 - ACM Private CA - Overview

## What is ACM Private CA?

A managed service to create a **private Certificate Authority (CA)** — root CA or subordinate CAs.

## What it issues

**End-entity X.509 certificates** — used by applications, but cannot be used to create new certificates.

## Key distinction vs ACM public certificates

| | ACM (public) | ACM Private CA |
|---|---|---|
| Trusted by | Everyone (public internet) | Only your organization's apps |
| Use on public internet | Yes | No |
| Use on internal services | Yes | Yes |
| Purpose | Public HTTPS | Internal/private TLS + authentication |

## Integrations

Same as ACM: ALB, CloudFront, API Gateway, Kubernetes, etc. — private certificates can be loaded just like public ones.

## Use Cases

- Encrypted TLS communication **internally**
- Cryptographically **sign code**
- Authenticate users, computers, API endpoints, IoT devices
- Create a **PKI (Public Key Infrastructure)** within an enterprise

## Exam Tip 🎯

- "Private certificates", "internal TLS", "enterprise PKI", "authenticate internal services" → **ACM Private CA**
- Not for public internet — only trusted within your organization
