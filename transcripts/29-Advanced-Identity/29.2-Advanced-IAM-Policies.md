# 29.2 - Advanced IAM Policies

## 1. Policy Evaluation Logic

When a request is made, IAM evaluates all applicable policies using this order:

```
Default: DENY
        │
        ▼
Is there an explicit DENY?
  YES → DENY (final, no matter what)
        │
        ▼
Is there an explicit ALLOW?
  YES → ALLOW
  NO  → DENY (implicit)
```

**Key rule:** Explicit DENY always wins over explicit ALLOW.

---

## 2. IAM Policies + S3 Bucket Policies (Union)

When an IAM principal takes action on S3, AWS evaluates the **union** of:
- The IAM policy attached to the user/role
- The S3 bucket policy attached to the bucket

### 4 Examples

| IAM Policy | S3 Bucket Policy | Result |
|---|---|---|
| Allow read/write | None | ✅ Allowed |
| Allow read/write | Explicit DENY for this role | ❌ Denied (explicit deny wins) |
| Empty (no S3 perms) | Allow read/write for this role | ✅ Allowed (bucket policy sufficient) |
| Explicit DENY | Allow read/write | ❌ Denied (explicit deny wins) |

---

## 3. Dynamic IAM Policies

Instead of creating one policy per user, use **policy variables** that resolve at runtime.

### Problem: per-user S3 home folders
Without dynamic policies → 1 IAM policy per user (doesn't scale).

### Solution: `${aws:username}` variable

```json
{
  "Effect": "Allow",
  "Action": ["s3:*"],
  "Resource": [
    "arn:aws:s3:::my-bucket/home/${aws:username}",
    "arn:aws:s3:::my-bucket/home/${aws:username}/*"
  ]
}
```

One policy for ALL users — `${aws:username}` is replaced at runtime with the actual IAM username.

---

## 4. Inline vs Managed Policies

| Type | Managed by | Reusable | Version control | Notes |
|---|---|---|---|---|
| **AWS Managed** | AWS | ✅ | AWS updates automatically | Good for standard job functions (admin, power user) |
| **Customer Managed** | You | ✅ | ✅ (rollback available) | Best practice — granular control, central change mgmt |
| **Inline** | You (embedded in principal) | ❌ | ❌ | 1:1 with principal; deleted if principal deleted; size-limited |

---

## Exam Tips

- ✅ Explicit DENY always wins — evaluated before ALLOW
- ✅ S3 actions evaluate **union** of IAM policy + S3 bucket policy
- ✅ Dynamic policy variable: `${aws:username}` — one policy for all users
- ✅ Customer managed > inline — reusable, versioned, auditable
- ✅ Inline policy: deleted when principal is deleted; not reusable; no version control
