# 29.4 - Microsoft Active Directory & AWS Directory Services

## What is Microsoft Active Directory (AD)?

AD is software found on **Windows Server** that manages a database of objects:
- User accounts, computers, printers, file shares, security groups

**Domain Controller** = the central server that holds all user accounts. All Windows machines in the network connect to it to validate logins.

```
Domain Controller (has John / password)
        │
   ┌────┼────┬────────┐
   ▼    ▼    ▼        ▼
 PC1  PC2  PC3  ...  PCn
(all validate credentials against the DC)
```

A group of trees in AD = **forest** (terminology only).

---

## AWS Directory Services — 3 Flavors

| Service | Description | Users managed in | On-premise AD required? |
|---|---|---|---|
| **AWS Managed Microsoft AD** | Full AD in AWS with trust to on-premise AD | Both AWS and on-premise | Optional |
| **AD Connector** | Proxy that redirects auth requests to on-premise AD | On-premise only | ✅ Yes |
| **Simple AD** | Standalone AD-compatible directory in AWS | AWS only | ❌ No |

---

### 1. AWS Managed Microsoft AD

- Creates a real AD in AWS
- Supports **MFA**
- Can establish a **trust relationship** with on-premise AD
- Users can exist in both AWS AD and on-premise AD
- Use when: you want a full AD in AWS, optionally connected to on-premise

```
AWS Managed AD ←——trust——→ On-premise AD
  (AWS users)                (on-prem users)
  Both accessible from either side
```

---

### 2. AD Connector

- **Proxy only** — no user data stored in AWS
- Redirects all auth requests to your on-premise AD
- Supports **MFA**
- Users are managed **only** in on-premise AD
- Use when: you want to keep users on-premise and just proxy to AWS

```
User → AD Connector → On-premise AD (validates login)
```

---

### 3. Simple AD

- Standalone AD-compatible directory in AWS
- **Does NOT integrate with on-premise AD**
- No trust relationship
- Use when: you need basic AD in AWS with no on-premise AD

---

## Why have AD in AWS?

EC2 instances running **Windows** can join the domain controller — they share logins and credentials across all machines. Having AD in AWS keeps this closer to your EC2 instances.

---

## Exam Tips — Decision Table

| Scenario | Answer |
|---|---|
| Need full AD in AWS with optional on-premise trust | **AWS Managed Microsoft AD** |
| Want to proxy users to existing on-premise AD | **AD Connector** |
| Need standalone AD in AWS, no on-premise | **Simple AD** |
| Need MFA | AWS Managed AD or AD Connector (both support MFA) |
| Users managed ONLY on-premise | **AD Connector** |
