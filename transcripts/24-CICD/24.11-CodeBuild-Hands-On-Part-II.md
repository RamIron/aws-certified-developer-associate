# 24.11 - CodeBuild Hands On Part II

**Status: Skipped (hands-on only)**

## Summary

Completes the CodeBuild hands-on and integrates it into CodePipeline:

1. **Added `buildspec.yml` to the GitHub repo** — includes a `grep` command in the `build` phase that tests for the word "Congratulations" in `index.html`. Build succeeds only if the word is found.

2. **Webhook auto-triggered a build** — pushing to GitHub fired a new CodeBuild run automatically (GitHub hook → CodeBuild).

3. **Build phases visible in the console**: submitted → queued → provisioning → download_source → install → pre_build → build → post_build → upload_artifacts → finalizing → completed.

4. **Removed the GitHub webhook** from the CodeBuild project — CodePipeline will now be the one triggering CodeBuild (not GitHub directly).

5. **Added a TestCode stage to CodePipeline** — between Source and Deploy, using the `MyFirstBuild` CodeBuild project. Input: `SourceArtifact`. Output: `OutputOfTest`.

6. **End-to-end test of the pipeline**:
   - Changed "Congratulations" → "horrible" in `index.html` → build **failed** → pipeline stopped, nothing deployed
   - Changed back to "congratulations" → build **succeeded** → pipeline continued → Dev environment updated

## Key Takeaway

> When CodeBuild is the submitter in Build History, it was triggered by **GitHub** (webhook). When **CodePipeline** is the submitter, it was triggered by the pipeline. You can tell them apart in the Build History view.
