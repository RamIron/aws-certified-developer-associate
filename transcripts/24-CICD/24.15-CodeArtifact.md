# 24.15 - CodeArtifact

## Key Concepts

### 1. What is CodeArtifact?
- **Artifact management system** — secure, scalable, cost-effective
- Stores software **dependencies** (packages your code depends on)
- Integrates with: Maven, Gradle, npm, yarn, twine, pip, NuGet
- Both **developers** and **CodeBuild** can pull dependencies from CodeArtifact directly

### 2. CodeArtifact as a Proxy + Cache
- Acts as a **proxy** to public artifact repositories (npm registry, PyPI, Maven Central, NuGet, etc.)
- Developers point their package manager (npm, pip…) at CodeArtifact instead of the public repo
- Benefits:
  - **Network security**: devs only talk to CodeArtifact, not the public internet
  - **Caching**: packages fetched once are stored — if the public package disappears, your copy survives

### 3. Structure: Domains and Repositories
- Artifacts live within **domains** → each domain contains **repositories**
- Repositories can hold packages from multiple sources (proxied public + internal)

### 4. Publishing Your Own Packages
- Developers can push internal packages into CodeArtifact
- All artifacts (internal + external) live in one place within your VPC
- CodeBuild can pull from CodeArtifact instead of public repos

### 5. EventBridge Integration
- Package events (created / modified / deleted) → emit to **EventBridge**
- From EventBridge: trigger Lambda, Step Functions, SNS, SQS, CodePipeline, etc.
- Example pipeline: package updated → EventBridge → CodePipeline → CodeBuild (rebuild) → CodeDeploy (deploy with updated dep)

### 6. Cross-Account Access
- Same-account: IAM policy on the user/role
- Cross-account: **resource policy** on the CodeArtifact repository
- Cross-account grants access to **all packages** in the repo — you cannot restrict to specific packages

## Exam Tips
- "Artifact management within AWS" → CodeArtifact
- Acts as a proxy + cache for public repos (npm, pip, Maven, NuGet)
- Package change event → EventBridge → can trigger full CI/CD pipeline
- Cross-account CodeArtifact access → **resource policy** (not IAM policy)
- Access is all-or-nothing per repo: can't grant access to specific packages only
