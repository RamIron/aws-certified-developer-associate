# 24.14 - CodeDeploy for EC2 and ASG

## Key Concepts

### 1. Hooks in appspec.yml
- Hooks run scripts at specific points in the lifecycle (BeforeInstall, AfterInstall, ApplicationStart, ValidateService, etc.)
- Used to **verify** the deployment after each phase (e.g. run health checks, smoke tests)

### 2. ASG — In-Place Deployments
- Works the same as regular EC2 in-place
- **Extra benefit**: if a new EC2 instance is added to the ASG (e.g. via scaling), CodeDeploy **automatically deploys** the latest revision to it

### 3. ASG — Blue/Green Deployments
- A new ASG is created with the same settings (copied from the original)
- CodeDeploy deploys v2 to the new ASG
- ELB gradually shifts traffic from v1 ASG → v2 ASG
- You choose **how long to keep the old ASG** before terminating it
- Flow:
  1. Original ASG (v1) running behind ELB
  2. New ASG created (copied settings), v2 deployed to it
  3. ELB receives traffic from both v1 and v2 temporarily
  4. If healthy → v1 ASG terminated

### 4. Rollbacks
- **Automatic**: triggered on deployment failure or CloudWatch Alarm
- **Manual**: initiated by the operator
- **Disable**: rollbacks can be disabled for a deployment
- **Key exam point**: a rollback is NOT a restore — CodeDeploy performs a **new deployment** using the last known good revision. It does not go back in time.

## Exam Tips
- New instances added to an ASG → automatically get the latest CodeDeploy revision (in-place)
- Blue/green ASG: new ASG is created with **copied settings**, old one kept for configurable time
- Rollback = **new deployment** of last known good revision (not a restore)
- Rollback triggers: deployment failure OR CloudWatch Alarm
