## Key Observations

### Source Providers in CodePipeline
CodeCommit (**discontinued**), Amazon ECR, Amazon S3, Bitbucket, GitHub v1, **GitHub v2** (recommended), GitHub Enterprise Server, GitLab, GitLab Self-Managed.

### IAM Service Role — confirmed in practice
- CodePipeline creates a service role automatically on pipeline creation
- May be missing Beanstalk permissions → manually attach `AdministratorAccess-AWSElasticBeanstalk` to the role
- Confirms the exam rule: if CodePipeline can't perform an action → check its IAM service role

### Trigger
- Pipeline triggers on push to a specified branch (e.g. `main`)
- Configured as a filter: "push to branch = main"

### Manual Approval — confirmed in practice
- Added as an action group within a stage
- Optional: SNS topic, URL for review, comments
- Pipeline is blocked until a human approves or rejects
- Only after approval does the next action group (e.g. deploy to prod) execute

### Action Groups within a Stage
- A stage can contain multiple **sequential** action groups
- Example: "Deploy to Prod" stage had two groups: (1) Manual Approval → (2) Deploy to Beanstalk prod

### Pipeline History
- Left-hand side of console shows all runs
- Each run shows: duration, success/failure, commit it corresponds to

### Build Providers available
CodeBuild and Jenkins.

## Exam Tips
- **CodeCommit is discontinued** — GitHub v2 is the recommended source
- CodePipeline can't deploy to Beanstalk → attach Beanstalk policy to its IAM service role
- Multiple action groups in one stage run **sequentially**
- Manual approval can be placed before any action group in any stage
