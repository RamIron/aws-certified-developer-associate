# 24.13 - CodeDeploy Hands On

**Status: Skipped (hands-on only)**

## Summary

End-to-end hands-on deploying a sample app to an EC2 instance using CodeDeploy.

### IAM Roles Created
- **CodeDeployServiceRoleForEC2** — service role for CodeDeploy (AWS service → CodeDeploy)
- **EC2RoleForCodeDeploy** — instance profile for EC2 with `AmazonS3ReadOnlyAccess` (so the agent can pull the revision from S3)

### EC2 Instance Setup
- Launched an Amazon Linux t2.micro instance (DemoWebServer)
- Security group: SSH (22) + HTTP (80)
- **Manually installed the CodeDeploy agent** via SSH:
  1. `sudo yum update`
  2. `sudo yum install ruby`
  3. Download install script from AWS
  4. `chmod +x install` → `sudo ./install auto`
  5. `sudo service codedeploy-agent status` — confirms agent is running

### CodeDeploy Application
- Application name: `DemoApplication`
- Compute platform: EC2/On-Premises
- Deployment group: `DevelopmentGroup`
  - Deployment type: **In-place**
  - EC2 instance selected via **tag**: `Environment = Development`
  - Deployment config: `CodeDeployDefault.AllAtOnce`
  - Load balancer: disabled (no ASG in this demo)

### Tags — How CodeDeploy Targets Instances
- EC2 instance tagged: `Environment = Development`
- CodeDeploy deployment group filters by that tag → "1 unique matched instance"
- This is how you separate dev/prod targets without hardcoding IPs

### S3 Revision (SampleApp_Linux.zip)
- Uploaded to S3 bucket in the same region as CodeDeploy
- Contains:
  - `index.html` — the web page
  - `appspec.yml` — CodeDeploy instructions
  - Shell scripts: `install_dependencies.sh`, `start_server.sh`, `stop_server.sh`

### appspec.yml structure
```yaml
files:
  - source: index.html
    destination: /var/www/html   # Apache web root

hooks:
  BeforeInstall:
    - location: scripts/install_dependencies.sh   # installs httpd
  ApplicationStart:
    - location: scripts/start_server.sh           # starts httpd
  ApplicationStop:
    - location: scripts/stop_server.sh            # stops httpd if running
```

### Lifecycle Events (visible in console)
`ApplicationStop → DownloadBundle → BeforeInstall → Install → AfterInstall → ApplicationStart → ValidateService`

### Common Gotcha from this lesson
> First deployment **failed** because the EC2 instance had no IAM role attached.
> Fix: Actions → Security → Modify IAM role → attach `EC2RoleForCodeDeploy`.
> Without this, the agent cannot pull the revision from S3.
