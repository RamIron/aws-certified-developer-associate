Topic 1 — EC2 Instance Metadata Service (IMDS)Tema 1 — Metadatos de instancia EC2 (IMDS)
How Instances Learn About ThemselvesCómo las instancias se informan sobre sí mismas
Core concept:Concepto clave: IMDS lets an EC2 instance learn about itself without an IAM Role. The data is available at the link-local address http://169.254.169.254 — only reachable from inside the instance.IMDS permite que una instancia EC2 se informe sobre sí misma sin un Rol de IAM. Los datos están disponibles en la dirección link-local http://169.254.169.254 — solo accesible desde dentro de la instancia.
What you CAN retrieveLo que SÍ puedes recuperar
  • Instance ID, type, AMI IDID de instancia, tipo, ID de AMI
  • Public IP and private IPIP pública e IP privada
  • IAM Role nameNombre del Rol de IAM
  • Temporary credentials for the roleCredenciales temporales para el rol
  • User Data (launch script)Datos de usuario (script de inicio)
What you CANNOT retrieveLo que NO puedes recuperar
  • IAM Policy attached to the rolePolítica de IAM adjunta al rol
  • Any data from other instancesDatos de otras instancias

Exam trap: IMDS gives the role name, never the policy document.Trampa del examen: IMDS da el nombre del rol, nunca el documento de política.

Metadata vs User Data:Metadatos vs Datos de usuario: Metadata = information about the instance (IP, role, type). User Data = the bootstrap script that ran at launch. Both accessible via 169.254.169.254 but at different paths.Metadatos = información acerca de la instancia (IP, rol, tipo). Datos de usuario = el script de bootstrap que se ejecutó al inicio. Ambos accesibles vía 169.254.169.254 pero en rutas diferentes.

Topic 2 — AWS CLI with MFATema 2 — AWS CLI con MFA
Using MFA Authentication from the CLIUsar autenticación MFA desde la CLI
Key mechanism:Mecanismo clave: To make CLI calls that require MFA, you must call STS GetSessionToken. This returns temporary credentials you use for subsequent calls. Your long-term credentials alone are not enough.Para hacer llamadas CLI que requieren MFA, debes llamar a STS GetSessionToken. Esto devuelve credenciales temporales que usas para llamadas posteriores. Tus credenciales a largo plazo por sí solas no son suficientes.
1
Call aws sts get-session-token with --serial-number <MFA-device-ARN> and --token-code <6-digit-code>Llama a aws sts get-session-token con --serial-number <ARN-dispositivo-MFA> y --token-code <código-6-dígitos>
2
STS returns: AccessKeyId + SecretAccessKey + SessionToken + ExpirationSTS devuelve: AccessKeyId + SecretAccessKey + SessionToken + Expiration
3
Set AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY, AWS_SESSION_TOKEN from the response and make your API callsEstablece AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY, AWS_SESSION_TOKEN de la respuesta e haz tus llamadas API
Exam pattern:Patrón del examen: "MFA with CLI" always points to STS GetSessionToken. The serial number is the ARN of the virtual MFA device registered with the IAM user."MFA con CLI" siempre apunta a STS GetSessionToken. El número de serie es el ARN del dispositivo MFA virtual registrado con el usuario de IAM.

Topic 5 — AWS Signature Version 4 (SigV4)Tema 5 — Versión de firma AWS 4 (SigV4)
How Every AWS API Request Gets AuthenticatedCómo se autentica cada solicitud de API de AWS
What is SigV4?¿Qué es SigV4? Every request to AWS APIs must be cryptographically signed using SigV4. The AWS CLI and SDKs handle this automatically — you only need to understand it for custom HTTP clients and pre-signed URLs.Cada solicitud a las API de AWS debe ser firmada criptográficamente usando SigV4. La CLI de AWS y los SDK manejan esto automáticamente — solo necesitas entenderlo para clientes HTTP personalizados y URLs prefirmadas.
Method 1 — Authorization HTTP HeaderMétodo 1 — Encabezado HTTP de autorización
Authorization: AWS4-HMAC-SHA256
Credential=AKID/20231201/us-east-1/s3/aws4_request,
SignedHeaders=host;x-amz-date,
Signature=abc123...
Used by the AWS CLI and SDK for all regular API calls.Utilizado por la CLI de AWS y el SDK para todas las llamadas API regulares.
Method 2 — Query String ParameterMétodo 2 — Parámetro de cadena de consulta
https://bucket.s3.amazonaws.com/file.pdf
?X-Amz-Algorithm=AWS4-HMAC-SHA256
&X-Amz-Credential=...&X-Amz-Expires=3600
&X-Amz-Signature=abc123...
Used by S3 pre-signed URLs. The signature is embedded directly in the URL.Utilizado por URLs prefirmadas de S3. La firma está incrustada directamente en la URL.
Exam shortcut:Atajo del examen: "Pre-signed URL" → always uses X-Amz-Signature in the query string (Method 2). Regular SDK/CLI calls → always use the Authorization HTTP header (Method 1)."URL prefirmada" → siempre usa X-Amz-Signature en la cadena de consulta (Método 2). Llamadas SDK/CLI regulares → siempre usa el encabezado HTTP Authorization (Método 1).
