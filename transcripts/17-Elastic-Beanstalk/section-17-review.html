What is Elastic Beanstalk?¿Qué es Elastic Beanstalk?

Elastic Beanstalk is a Platform-as-a-Service (PaaS) that lets you deploy web applications and services without managing the underlying infrastructure. You upload your code and Beanstalk automatically handles capacity provisioning, load balancing, auto-scaling, and health monitoring — all built on top of familiar AWS services like EC2, ASG, ELB, and RDS. Elastic Beanstalk es una plataforma como servicio (PaaS) que te permite desplegar aplicaciones web sin gestionar la infraestructura subyacente. Subís tu código y Beanstalk se encarga automáticamente del aprovisionamiento de capacidad, balanceo de carga, auto-escalado y monitoreo de salud — todo construido sobre servicios AWS conocidos como EC2, ASG, ELB y RDS.

Lifecycle PolicyPolítica de Ciclo de Vida

Beanstalk stores application versions in S3. The limit is 1000. Without cleanup, you eventually can't deploy. Beanstalk almacena versiones de la aplicación en S3. El límite es 1000. Sin limpieza, eventualmente no podrás desplegar.

Versions storedVersiones almacenadas
LIMIT

At 1000 versions → new deployments are BLOCKED until old ones are removed. Al llegar a 1000 versiones → los nuevos despliegues quedan BLOQUEADOS hasta que se eliminen las antiguas.

🔢

By CountPor Número

Keep only the last N versions (e.g., keep last 200). Older ones are deleted. Mantén solo las últimas N versiones (ej., las últimas 200). Las anteriores se eliminan.

📅

By TimePor Tiempo

Delete versions older than N days (e.g., older than 180 days). Elimina versiones con más de N días (ej., más de 180 días).

🛡

Active = ProtectedActivo = Protegido

Versions currently deployed to an environment are never deleted. Las versiones actualmente desplegadas en un entorno nunca se eliminan.

📦

S3 Source BundlePaquete de Fuente S3

Choose to retain (audit trail) or delete (save cost) the S3 zip file. Elegís retener (trazabilidad) o eliminar (ahorro de costos) el archivo zip en S3.

Lifecycle cleanup runs via a Beanstalk service role that needs IAM permissions to delete from S3. La limpieza del ciclo de vida se ejecuta a través de un rol de servicio de Beanstalk que necesita permisos IAM para eliminar de S3.

EB ExtensionsExtensiones de EB

Every setting in the Beanstalk console can also be configured as code inside your source zip. This is infrastructure-as-code for Beanstalk. Toda configuración de la consola de Beanstalk también se puede definir como código dentro del zip de tu aplicación. Esto es infraestructura-como-código para Beanstalk.

Three Rules (all required)Tres Reglas (todas requeridas)

📁

DirectoryDirectorio

Must be in .ebextensions/ at the root of your source code. The dot matters. Debe estar en .ebextensions/ en la raíz de tu código fuente. El punto importa.

📄

File extensionExtensión de archivo

Files must end in .config (e.g., environment-variables.config, logging.config). Los archivos deben terminar en .config (ej., environment-variables.config, logging.config).

✏️

FormatFormato

Content must be YAML or JSON. The .config extension doesn't restrict format. El contenido debe ser YAML o JSON. La extensión .config no restringe el formato.

Example: Setting environment variablesEjemplo: Establecer variables de entorno

# .ebextensions/environment-variables.config option_settings: aws:elasticbeanstalk:application:environment: DB_URL: "jdbc:postgresql://my-rds.amazonaws.com:5432/mydb" DB_USER: "admin" NODE_ENV: "production"
⚠ Resources created via EB Extensions (RDS, ElastiCache, DynamoDB) are tied to the environment. Delete the environment → those resources are deleted too. Los recursos creados mediante EB Extensions (RDS, ElastiCache, DynamoDB) están vinculados al entorno. Eliminar el entorno → esos recursos también se eliminan.

CloudFormation Under the HoodCloudFormation Bajo el Capó

Beanstalk doesn't provision resources directly — it creates a CloudFormation stack for each environment. CloudFormation does the actual work. Beanstalk no provisiona recursos directamente — crea un stack de CloudFormation por cada entorno. CloudFormation es quien hace el trabajo real.

🔍

1 Env = 1 Stack1 Entorno = 1 Pila

Each Beanstalk environment maps to exactly one CloudFormation stack. Visible in the CF console. Cada entorno de Beanstalk corresponde exactamente a un stack de CloudFormation. Es visible en la consola de CF.

⚙️

What it createsLo que crea

ASG, Launch Config, ELB, Target Groups, Security Groups, CloudWatch Alarms, Scaling Policies. ASG, Launch Config, ELB, Target Groups, Security Groups, CloudWatch Alarms, Políticas de escalado.

🚀

Power unlockDesbloqueador de energía

EB Extensions + CloudFormation = provision any AWS resource beyond the console UI. EB Extensions + CloudFormation = provisionar cualquier recurso AWS más allá de la consola UI.
